# 홍보잇다 모바일 UI 검토

2026-10-14 · `feature/UI-Screen` · 기준 `dfb5a2e` · 선행 로컬 검토 기록.

이후 사용자에게 커밋·푸시·main 병합을 승인받은 최종 검토는 [GitHub 통합 검토](feedback/2026-10-14-final-integration-review.md)에 기록한다. 아래 결과는 선행 로컬 검토 당시의 범위다.

현재 브랜드와 화면 구조를 유지하고 참고 이미지에서는 동선·하단 메뉴·정보 위계만 차용한다. 교수 피드백과 현재 지침을 확인했다. `DESIGN.md`는 저장소에 없으며 `docs/archive/DESIGN_MASTER.md`는 역사 자료로 확인했다.

## Discover → Define

모바일 UX, 접근성, 신뢰성, 시각 디자인 관점에서 소스와 Chromium 실행 화면을 독립 검토했다. 일부 보조 에이전트가 실행 한도에 도달하여 최종 통합과 재검증은 주 작업자가 수행한다. 실제 사용자 인터뷰나 실물 휴대전화 테스트는 수행하지 않았다.

| 화면 | 발견 문제와 사용자 영향 | 심각도 | 수정 |
|---|---|---|---|
| 사진 등록 | 사진 선택 전에는 출력 선택이 없어 결과 종류를 미리 고를 수 없음 | 높음 | 선택기를 항상 표시 |
| 사진 등록 | 360×640에서 예시·큰 업로드 영역 때문에 다음 버튼이 하단 메뉴 아래에 위치 | 높음 | 영역 축소, 예시를 다음 버튼 아래 펼침 안내로 이동 |
| 진행 표시 | 사진/설명/결과 축약과 다른 화면 용어가 달라 단계 의미가 불분명 | 중간 | 사진 등록/정보 입력/결과 확인으로 통일 |
| 정보 입력 | 비어 있는 상품명의 오류 안내가 숨겨져 진행 불가 이유가 안 보임 | 높음 | 필수 안내·인라인 오류·진행 조건 표시 |
| 정보 입력 | 가게 이름을 적을 별도 입력이 없음 | 중간 | 선택 입력 추가, 상품명만 필수 |
| 메뉴 재진입 | 같은 작업에서 영상 선택이 둘 다로 초기화됨 | 높음 | 동일 작업의 단계·출력 선택 보존 |
| 새 작업 | 새 홍보물도 이전 출력 선택을 가져갈 수 있음 | 중간 | 새 작업은 둘 다로 초기화 |
| 초안 재진입 | 이어서 사용 안내가 주 조작 위에 한 줄을 더해 짧은 화면을 밀 수 있음 | 중간 | 안내를 접근성 상태 알림으로 유지, 선택된 사진·출력은 화면에 보존 |
| 이미지 결과 | 준비 실패 시 저장·확대만 비활성이고 재시도 경로 없음 | 높음 | 준비 중/실패/성공 상태, 다시 준비 버튼 |
| 결과 | 이미지가 준비되기 전에 성공 피드백 발생 | 중간 | 이미지 준비 완료 시 피드백 |
| 결과 | 결과 단계 표시가 없어 사진·정보 수정 경로의 일관성이 약함 | 중간 | 같은 단계 표시 연결, 완료한 단계로 이동 |
| 결과 | 단계 표시 추가 후 390×844의 저장 버튼 끝이 메뉴에 걸림 | 중간 | 결과 카드 상단 여백 조정, 재검증 |
| 로그인 | 연결되지 않은 로그인 제출이 성공처럼 홈으로 이동 | 높음 | 연결 준비 중 안내, 미연결 입력·제출 비활성화 |

## Develop → Deliver (완료)

1. **핵심 동선**: 동일 작업의 메뉴 재진입·홈 이동·내 홍보물 재열기에서 초안을 보존한다. 새 작업은 둘 다로 시작한다. 상품명만 필수이며 가게 이름·소개·알리고 싶은 점은 선택 입력이다. 입력 옆의 오류 안내와 이미지 재시도를 검증했다.
2. **모바일 사용성**: 빈 화면과 사진 선택 후 모두 진행 표시 → 사진 영역 → 출력 선택 → 다음으로가 360×640·390×844에서 하단 메뉴 위에 들어온다. 390×693도 통과했다. 기존 스타일이 되살린 여백을 렌더링 검사에서 발견해 수정했다. 320×568·가로형·큰 글자는 자연스럽게 스크롤한다.
3. **시각적 마감**: 이미지·영상의 표시 영역, 제목·보기 조작, 저장 버튼을 같은 규격으로 유지했다. 둘 다는 이미지→영상→문구, 포스터는 이미지→문구, 영상은 영상→문구 순서로 열리며 문구가 먼저 나오지 않는다. 안내 문구와 비활성 하위 기능은 노출되지 않는다. 결과 단계에서 사진·정보로 돌아가는 조작도 연결했다.

## 실제 수행한 검증

모든 명령은 앱 폴더에서 실행했다. Chromium과 로컬 Noto Sans KR 글꼴을 사용했다. 유료 생성 API 호출은 하지 않았다.

| 검사 | 결과 | 확인 범위 |
|---|---|---|
| `pnpm exec tsc --noEmit` | 통과 | TypeScript 정적 검사 |
| `pnpm build` | 통과 | Vite 프로덕션 번들 |

| `pnpm verify:usability` | 20 프로필 통과 | 위 폭, 320×568 / 390×450 / 844×390. 메뉴 초점·키보드 조작, 터치 영역, 업로드·교체·후진·초안, 긴 입력, 화면 겹침·가로 넘침 |
| `git diff --check` | 통과 | 공백 오류 없음 |

실패 상황은 테스트 페이지에서만 Canvas/clipboard/MediaRecorder 등을 주입해 검증했다. 실제 로컬 생성·다운로드·복사와 구분하며 생산 코드에는 모의 응답 경로를 넣지 않았다. 세 검토 단계에서 발견한 높은 우선순위의 UI 문제는 모두 수정했다.

최종 초안 상태 알림 조정 후 360×640 일반·큰 글자 모드의 메뉴·홈 재진입, 한 화면 배치와 오류 복구를 다시 통과했다. 최종 제출용 캡처에서 가게 이름의 결과 반영을 확인했다. 최종 TypeScript·빌드도 통과했다. 제출용 화면은 `output/mobile-completion/deliverables/`에 9장으로 정리했다.

## 수정한 파일

앱 폴더 기준 경로다.

- `src/App.tsx`: 초안 보존, 선택 가게 이름, 상품명 검증, 이미지 준비 상태·재시도, 결과 단계 연결.
- `src/PhotoStep.tsx`: 항상 표시되는 출력 선택, 작은 업로드 영역, 예시 안내 펼침, 다음으로.
- `src/StepProgress.tsx`: 사진 등록 / 정보 입력 / 결과 확인 용어.
- `src/StudioScreens.tsx`: 미연결 인증 안내·비활성화.
- `src/focus-review.css`: 한 화면 배치, 단계 연결선, 오류·준비 상태, 결과 간격.
- `scripts/verify-mobile-flow.mjs`: 신규 동선·실패 복구·선택별 결과 검증.
- `scripts/verify-submission-ui.mjs`: 빈 업로드 검사와 변경된 버튼 이름.
- `scripts/verify-result-consistency.mjs`, `scripts/verify-integrated-usability.mjs`, `scripts/verify-expert-review.mjs`, `scripts/verify-usability-cycles.mjs`: 다음으로 버튼 이름 반영. 전문가·반복 검토 스크립트는 이번 실행 목록에 포함하지 않았다.
- `package.json`: `verify:mobile-flow` 명령 추가. 의존성 변경 없음.
- `MOBILE_UI_REVIEW.md`: 문제 기록·수정·실제 검증·미검증 범위·후속 확인.

## 통합 범위와 환경

- 앱은 현재 브라우저의 Canvas 포스터, MediaRecorder 영상, 규칙 기반 문구를 만드는 체험형 프로토타입이다. AI 생성·인증·클라우드 저장 API가 연결된 서비스가 아니다.
- 출력 선택은 표시 결과와 포스터 렌더링을 제어한다. 영상 파일은 저장 요청 때 준비한다. 선택하지 않은 유료 API 호출은 없다.
- 내 홍보물과 제작 초안은 현재 열린 창의 메모리에 보관한다. 새로고침 전 저장·복사 안내를 유지한다.
- 실물 휴대전화·Android/iOS 키보드·Safari는 미검증이다. 키보드는 뷰포트 높이 축소와 초점 이동으로 시뮬레이션했다.
- 공유 API, 실제 로그인, AI 생성, 영구 저장은 미연결이다. 연결되지 않은 기능을 정상 동작한다고 표시하지 않는다. 내 홍보물은 현재 창에서만 보관하며 로딩 지연이 없는 메모리 목록이므로 가짜 로딩을 만들지 않았다.
- Figma: https://www.figma.com/design/ULjjjsqEBntBLpqVlKksiG . 새 독립 파일에 홈·사진 등록/선택·정보·결과의 편집 가능한 검토 화면 4개, 공통 컴포넌트 17개, 기존 색상 변수와 Noto Sans KR 스타일을 만들었다. 224개의 하위 노드(텍스트 76개, 인스턴스 21개 등)를 확인했고 전체 렌더링에서 제목 겹침을 수정했다. 기존 공유 파일·라이브러리는 변경하거나 게시하지 않았다.
- Figma 실시간 캡처 스크립트가 `Site Unavailable`, 자산 직접 업로드가 HTTP 405/413으로 차단되었다. 결과 그림은 기존 소개 일러스트를 사용한 배치 예시이며 실행 앱의 결과를 그대로 복제한 디자인이라고 주장하지 않는다. 로고는 기존 SVG를 사용했다.
- 수정 전 캡처: 작업 공간 `output/mobile-completion/before/`. 수정 후 앱 캡처: `output/mobile-completion/after/`, 결과 일관성 검증: `output/mobile-completion/pass-3/`, 상세 사용성: `output/mobile-completion/usability/`.
- 후속 확인: 실제 휴대전화에서 키보드·파일 저장·음성·영상 형식을 확인한다. 실제 생성·인증·저장·공유 API는 별도 개발 범위에서 연결한다.
