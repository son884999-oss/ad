# 회원가입 설정 안내 (Supabase · 카카오 · Google · Vercel)

코드는 끝나 있습니다(`src/auth.ts`, `src/cloudRecords.ts`, `api/account-delete.js`, 점검 `npm run verify:auth`). 아래는 **계정이 있어야 하는 설정**이라 직접 하셔야 합니다. 키 값은 채팅·문서·커밋에 붙이지 말고 `.env.local`과 Vercel에만 넣습니다.

## 1. Supabase 프로젝트 (약 10분)

1. [supabase.com](https://supabase.com) → Sign in → **New project**. 이름 `hongboitda`, DB 비밀번호는 따로 보관, **Region: Northeast Asia (Seoul)**, Free.
2. **Project Settings → Data API**(또는 첫 화면 **Connect**)의 **Project URL** → `.env.local`의 `VITE_SUPABASE_URL=`
3. **Project Settings → API Keys**
   - **Publishable key**(`sb_publishable_…`) → `VITE_SUPABASE_ANON_KEY=` (공개돼도 되는 키)
   - **Secret key**(`sb_secret_…`) → `SUPABASE_SERVICE_ROLE_KEY=` (**관리자 키, 절대 공개 금지**, 회원 탈퇴에만 서버에서 씀)
   - 예전 화면이면 **Legacy API keys** 탭의 `anon`, `service_role`.
4. **SQL Editor → New query** → `docs/supabase/schema.sql` 전체 붙여 넣기 → **Run**.
   - "destructive operations" 경고가 뜨면 그대로 실행해도 됩니다. `drop policy if exists`(같은 이름의 보안 규칙을 다시 만들기 위한 줄) 때문이고, 표나 데이터를 지우지 않습니다.
5. **Authentication → Sign In / Providers → Email**: 켜기. 내부 QA 동안 **Confirm email은 끄기**(기본 메일은 시간당 몇 통, 팀원 주소로만 보냄). 공개 서비스 전에는 켜고 SMTP(메일 발송 서비스)를 연결.
6. **Authentication → URL Configuration**
   - Site URL: `http://localhost:5173` (배포 후 Vercel 주소로)
   - Redirect URLs: `http://localhost:5173/**`, `https://*.vercel.app/**` (직접 도메인이 생기면 그 주소도)
7. `.env.local`을 저장한 뒤 개발 서버를 껐다 켭니다(`npm run dev`). 메뉴 → 로그인 · 회원가입 → 이메일로 가입해 보면 됩니다.

## 2. 카카오 로그인

1. [developers.kakao.com](https://developers.kakao.com) → 내 애플리케이션 → **애플리케이션 추가하기**(앱 이름 홍보잇다).
2. **앱 키 → REST API 키** 복사(= Client ID).
3. **제품 설정 → 카카오 로그인**: 활성화 **ON**. **Redirect URI**에 `https://<프로젝트>.supabase.co/auth/v1/callback`.
4. **카카오 로그인 → 보안 → Client Secret**: 코드 생성, 활성화 상태 **사용함**.
5. **동의항목**: 닉네임(필수/선택), 카카오계정(이메일). 이메일 동의항목은 **비즈 앱 전환**이 필요할 수 있습니다. 이메일을 못 받으면 Supabase Kakao 설정의 "Allow users without an email"(있으면)을 켜세요.
6. **앱 설정 → 플랫폼 → Web 사이트 도메인**: `http://localhost:5173`, Vercel 주소.
7. Supabase **Authentication → Sign In / Providers → Kakao**: 켜기, REST API 키 → Client ID, Client Secret → Secret. 저장.

## 3. Google 로그인

1. [Google Cloud 콘솔](https://console.cloud.google.com) → 프로젝트 선택(또는 새로) → **APIs & Services → OAuth consent screen**: External, 앱 이름·지원 이메일 입력. 테스트 중에는 **Test users**에 QA 계정 추가.
2. **Credentials → Create credentials → OAuth client ID → Web application**
   - Authorized JavaScript origins: `http://localhost:5173`, Vercel 주소
   - Authorized redirect URIs: `https://<프로젝트>.supabase.co/auth/v1/callback`
3. 나온 Client ID / Client Secret → Supabase **Providers → Google**에 넣고 켜기.

## 4. Vercel 환경 변수 (배포할 때)

Settings → Environment Variables에 **Production과 Preview 둘 다**:

| 이름 | 값 |
|---|---|
| `VITE_SUPABASE_URL` | Project URL |
| `VITE_SUPABASE_ANON_KEY` | Publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | Secret key (서버 전용) |

`VITE_`로 시작하는 값은 **빌드할 때** 화면에 들어가므로, 넣거나 바꾼 뒤에는 **다시 배포(Redeploy)** 해야 적용됩니다. 나머지 AI 키는 [배포_체크리스트.md](배포_체크리스트.md).

## 5. 확인

- 로컬: 메뉴 → 로그인 · 회원가입 → 이메일 가입 → 메뉴에 이메일이 보이면 성공. 홍보물을 하나 만들고 Supabase **Table Editor → records**에 한 줄, **Storage → records**에 사진·포스터·영상 파일이 생기는지.
- 다른 브라우저에서 같은 계정으로 로그인 → 내 홍보물에 보이는지.
- 메뉴 → 회원 탈퇴 → Supabase에서 그 사용자와 파일이 지워지는지.
- 자동 점검: `npm run verify:auth` (가짜 Supabase로 가입·저장·로그아웃·탈퇴를 확인, 비용 없음).
