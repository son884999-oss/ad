# 디자인 개선 루프

`/loop`로 계속 돌리는 품질·디자인 개선 작업의 명령어와 기록입니다. 모바일 웹앱만 다룹니다(PC는 휴대폰 틀).

## 실행 명령어

Claude Code에 아래를 그대로 붙여 넣습니다(간격 없이 쓰면 스스로 속도를 정해 반복합니다). 멈추려면 Esc를 누르거나 "루프 멈춰"라고 말합니다.

```
/loop 홍보잇다 모바일 웹앱(C:\Users\82104\Desktop\ad\ad_prototype, 브랜치 feature/UI-Screen)의 품질과 디자인을 한 바퀴에 하나씩 올린다. 먼저 docs/자동작업_프롬프트.md 의 진행 규칙과 docs/디자인개선_루프.md 의 기록을 읽고 그대로 따른다. 한 바퀴: (1) 기록의 "다음 영역" 차례인 화면을 npm run audit:screens -- --shots <스크래치패드>/before 로 390×844 기본·쉬운 화면 캡처를 만들어 직접 본다. (2) 고령 소상공인 사용자를 기준으로 까다로운 디자이너 눈으로 문제 3개를 적고(정렬·여백·글자 위계·강조 버튼·색·아이콘·문구), 효과가 가장 큰 1개만 고른다. 이미 기록에 있는 변경을 되돌리거나 같은 곳을 다시 만지지 않는다. (3) ad_prototype 안에서만 작게 고친다. (4) npx tsc --noEmit -p . , npm run -s build, verify:easy·photo·records·video·ai·promo, verify-reference-rebuild, npm run audit:screens(문제 0개)가 모두 통과해야 한다. (5) after 캡처를 다시 만들어 before와 나란히 보고, 확실히 나아지지 않았으면 변경을 버린다. (6) 나아졌으면 커밋하고 origin/feature/UI-Screen 에 푸시한 뒤, docs/디자인개선_루프.md 기록 표에 한 줄(날짜·영역·문제·고친 것·커밋)을 추가하고 "다음 영역"을 다음 차례로 바꾼다. 유료 호출 금지, 브라우저 테스트는 /api 전체를 가짜 응답으로 막기, .env.local 읽지 않기, 팀 폴더 읽기만, main 머지 금지, 새 npm 패키지 설치 금지. 한 영역에서 고칠 것이 없으면 "없음"으로 기록하고 다음 영역으로 넘어간다. 모든 영역이 연속 두 바퀴 "없음"이면 루프를 멈추고 남은 큰 일(로드맵)을 보고한다.
```

## 영역 순서

1. 홈 → 2. 사진 넣기 → 3. 내용 쓰기 → 4. 결과: 포스터 → 5. 결과: 영상 → 6. 결과: 홍보 글 → 7. 메뉴 → 8. 내 홍보물 → 9. 로그인 → 10. 포스터 이미지 자체(템플릿·글자 배치) → 11. 쉬운 화면 전체 → 다시 1번

## 판단 기준

- 고령 사용자에게 쉬운 쪽: 더 큰 글씨, 더 적은 선택지, 한 화면에 한 가지 일.
- 한 화면에 주황색 주 버튼은 하나만 둡니다.
- 글자 14px 이상, 대비 4.5:1 이상, 누르는 곳 44px 이상(쉬운 화면 52px 이상).
- 새 색·새 글꼴을 들이지 않고 지금 있는 토큰(`--color-brand` 등)을 씁니다.
- 기능을 없애거나 흐름을 바꾸는 큰 변경은 하지 않고 [품질개선_로드맵.md](품질개선_로드맵.md)에 적습니다.
