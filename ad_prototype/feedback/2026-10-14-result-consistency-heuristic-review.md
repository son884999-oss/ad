# 결과 화면 UI 통합 및 휴리스틱 검토

- 일시: 2026-10-14, Asia/Seoul
- 범위: `feature/UI-Screen`의 이미지·영상·문구 결과 탭
- 요청: 결과 종류가 달라져도 저장·복사와 미리보기 조작의 위치를 일관되게 유지하고 휴리스틱 검토 수행
- 방법: 실제 Chromium 렌더링을 검토하고 사용자 과업을 자동 실행함. 실제 참가자를 모집한 사용성 실험은 수행하지 않음.
- 기준: [Jakob Nielsen, 10 Usability Heuristics for User Interface Design](https://www.nngroup.com/articles/ten-usability-heuristics/)

## 발견한 문제와 반영

| 기존 문제 | 영향 | 반영 내용 |
| --- | --- | --- |
| 이미지 저장은 왼쪽, 영상 저장은 오른쪽 | 탭을 바꿀 때 주요 행동의 위치를 다시 찾아야 함 | 저장·복사를 공통 컴포넌트의 전체 폭 버튼으로 통일 |
| 영상 재생과 저장이 같은 줄에 혼재 | 확인 작업과 결과 가져가기 작업이 경쟁함 | 확대·재생은 콘텐츠 안의 같은 오른쪽 아래 위치에 큰 원형 아이콘 버튼으로 배치, 저장·복사는 콘텐츠 바로 아래 |
| 문구 탭의 메타 정보·안내문이 복사 버튼을 아래로 밀어냄 | 세 탭의 수직 위계가 달라짐 | ‘미리보기’·‘기본 홍보 문구’·글자 수 행을 삭제하고 수정 안내는 결과 화면 공통 위치에 표시 |
| 문구 제목에만 과거 CSS의 22px 아래 여백이 남음 | 프레임과 버튼 좌표가 다름 | 제목·프레임·행동 영역에 공통 여백 규칙 적용 |
| 이미지 확대 시 프레임 전체 높이가 커짐 | 저장 버튼 위치가 바뀜 | 같은 프레임 안에서 확대·스크롤; 버튼 위치 유지 |
| 상태 메시지의 구조·표시 위치가 다름 | 성공·실패를 찾는 위치가 달라짐 | 공통 행동 영역 아래 상태/오류 메시지 표시; 빈 메시지 영역은 생성하지 않음 |
| 복사 실패 안내가 일반 상태 메시지와 같은 표현 구조 | 오류를 식별하기 어려움 | 실패 시 `role="alert"`와 기존 오류 색상 적용, 재시도 후 정상 상태로 복구 |

## 휴리스틱별 검토

| 기준 | 관찰과 조치 | 검증 범위 |
| --- | --- | --- |
| 1. 시스템 상태 표시 | 선택된 탭, 확대·재생 상태, 저장·복사 결과와 영상 준비/취소 상태를 표시 | 자동 동작 검증 통과 |
| 2. 현실 세계와의 대응 | 유형은 제목에서 확인하고 행동은 ‘저장하기’·‘복사하기’·‘크게 보기’·‘재생하기’로 표현 | 문구와 화면 검토; 대상 사용자의 이해도 측정은 미실시 |
| 3. 사용자 제어와 자유 | 확대 해제, 일시 정지, 영상 준비 취소, 내용 수정과 입력 보존 유지 | 자동 동작 검증 통과 |
| 4. 일관성과 표준 | 공통 프레임·전체 폭 주요 버튼·콘텐츠 안의 같은 위치에 큰 보조 조작 적용 | 14개 화면 조합에서 미리보기와 주요 버튼의 좌표·크기 차이 0px |
| 5. 오류 예방 | 준비되지 않은 이미지의 저장/확대 비활성화, 준비 중 상태를 유지하고 영상 취소 제공 | 렌더링과 생성 상태 검토; 취소 동작 검증 통과 |
| 6. 기억보다 인지 | 제목·텍스트 라벨·아이콘으로 결과 유형과 행동을 바로 확인 | 화면 검토와 선택 탭/버튼 검사 통과 |
| 7. 유연성과 효율 | 일반·간편 모드, 키보드 탭 이동, 이미지 확대와 텍스트 스크롤 유지 | 두 모드 및 ArrowRight/End 이동 검증 통과 |
| 8. 간결한 디자인 | 불필요한 메타 정보 행과 빈 상태 영역을 없애고 안내를 공통 위치로 모음 | 실제 화면 검토; 요청했던 숨김 기능 비노출 검사 통과 |
| 9. 오류 인지와 복구 | 실패를 오류 색상과 경고 역할로 표시하고 재시도를 안내 | 복사 실패를 주입한 뒤 정상 복사 재시도 검증 통과 |
| 10. 도움과 안내 | 공통 수정 안내가 실제 ‘내용 다시 수정하기’ 행동을 가리킴 | 해당 버튼으로 돌아갔을 때 상품명 보존 검증 통과 |

위 결과는 이번 범위의 휴리스틱 검토와 동작 검증이다. 서비스 전체의 접근성 준수, 이해도, 과업 성공률을 보증하는 판정은 아니다.

## 추가 사용자 피드백 반영

상단의 작은 보조 버튼은 실제 화면에서 눈에 잘 띄지 않았고, 설명 행이 콘텐츠를 나누고 있었다. 이를 바로잡기 위해 메타 정보 행을 제거했다. 확대·재생에는 기존 아이콘 체계의 돋보기·재생·정지 픽토그램을 적용했으며, 같은 위치에 104×104px의 진한 원형 버튼과 텍스트 라벨로 표시한다. 확대 해제와 일시 정지 상태도 해당 버튼에서 표시한다. 영상의 제품명은 보조 조작과 겹치지 않도록 위쪽으로 옮겼다.

- 세 결과 탭의 주요 버튼 좌표·크기 일치는 유지했다.
- 두 보조 조작의 크기와 아이콘 노출을 자동 검증했다.
- 보조 버튼의 계산된 전경/배경 명암비가 4.5:1 이상인지 확인했다.
- 불필요한 메타 정보 행이 렌더링되지 않는지 확인했다.
- 일반·간편 모드 14개 조합과 짧은/가로 화면의 동작을 변경 후 재검증했다.

## 자동 검사와 렌더링 검증

- `pnpm build`: 통과.
- `pnpm exec tsc --noEmit`: 통과.
- `git diff --check`: 통과.
- `scripts/verify-result-consistency.mjs`: 320·375·390·430·768·1024·1440px × 일반/간편 모드, 14개 조합 통과.
- 세 탭의 미리보기와 주요 버튼: 위치·크기 차이의 최댓값 0px; 버튼 글씨·안쪽 여백·모서리·배경색 일치.
- 390px 간편 모드 예: 미리보기 358×337.59375px, 주요 버튼 326×52px.
- 가로 넘침, 버튼 가림, 숨김 하위 메뉴 비노출, 확대 후 버튼 위치 유지, 탭 이동 시 재생 중지, 키보드 탭 이동, 복사 내용 일치 검증 통과.
- 복사 실패/재시도, PNG 다운로드, 영상 준비 취소, 영상 파일 다운로드, 수정 화면에서 상품명 보존 검증 통과.
- 짧은 화면 320×568·390×650px와 가로 화면 844×390px에서도 세 탭의 주요 버튼을 스크롤로 찾고 누를 수 있는지 별도 확인; 통과.

재현하려면 로컬 미리보기 서버를 실행한 상태에서 `pnpm verify:results`를 실행한다. 필요하면 `UI_BASE_URL`, `UI_BROWSER_CHANNEL` 또는 `UI_BROWSER_EXECUTABLE`, `RESULT_REVIEW_OUTPUT`을 지정할 수 있다.

## 남은 문제와 한계

1. 결과 화면 밖의 전체 메뉴에서, 320px 화면의 글씨 설정 영역을 자동 클릭하려 할 때 하단 고정 메뉴가 포인터를 가로채는 현상이 관찰됐다. 일반 모드 전환은 키보드로 수행할 수 있다. 터치·스크롤 동작은 별도 점검이 필요하며 이번 결과 탭 수정에는 포함하지 않았다.
2. 현재 브랜치의 결과는 ‘확인용 예시’다. 영상 화면은 사진 움직임을 보여 주며 완성된 저장 파일의 실제 플레이어가 아니다. 실제 영상 생성 API와 생성 품질은 이번 UI 검증 범위에 포함하지 않았다.
3. 실제 소상공인·시니어 사용자의 과업 시간과 오조작률은 측정하지 않았다. 배치 일치와 자동 동작 검증만으로 이를 추정하지 않는다.
