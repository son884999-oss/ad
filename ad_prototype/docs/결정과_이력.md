## 2. 날짜별 흐름

**10-13~14** — 교수 상담(`review/professor-consultation-20261013.pdf`), 화면 검토 증거(`review/evidence-*`). 화면 수정을 멈추고 인수인계서 작성.

**10-15** — 1차 MVP. 모바일·PC 화면 개선, 쉬운 모드 완성, 팀 모듈 B·C·D 통합(Gemini 사진 자동 채우기·홍보 글, D 포스터 렌더러), 사진 검사(흐림·어두움·실사), Higgsfield 영상 코드(Kling 2.5 Turbo 5초 720p).

**10-16** — 팀 모듈 A~F 기능 통합(아래 4절), 검증 스크립트 안정화, 독립 리뷰(코드·보안 / 화면 / 접근성) 중 CSS로 되는 것 반영. 웹 조사로 품질 로드맵 작성.
- 사고: `verify:ai`가 영상 요청을 막지 않은 채 실제 키로 2~3번 돌아 영상이 최대 6건 만들어졌을 수 있음 → 모든 검증 스크립트가 `/api` 전체를 가짜 응답으로 막게 고치고 `VIDEO_ENABLED` 스위치 추가.

**10-17** — 모바일 전용 결정, 개발자 모드 폐지. 품질 개선 루프(홍보 글·포스터·영상·화면 4영역, 목표 90점)를 돌려 모두 90점 이상으로 끝냄. 포스터 색 추출은 colorthief 대신 직접 구현(의존성 없음). 실제 AI 영상 위 자막 합성. 무료 Gemini 키 하루 20번 한도 확인.

**10-18** — 배포 전 검토. 기관 Claude(COPA) 키 연결. 고급형 콘셉트 영상 실제 확인(세계 전환은 되나 가짜 글자·밀가루가 제품을 덮음·제품이 작음). Gemini로 배경 바꾸기를 시험해 보니 Higgsfield 장면만큼 좋고 훨씬 빠름 → 고급형 구조 재논의 → 밤에 "기본형 + 배경 스위치"로, 다음 날 C안으로 확정. 다중 에이전트 품질 목표(95점)는 영상 한도·Gemini 한도·2시간 제한으로 79점에서 종료.

**10-19** — C안 구현(배경 팝업, `api/background`, 결과 사진 고르기, 고급형 화면 숨김). 카톡에서 영상이 3초로 잘리던 문제 해결(조각난 MP4를 보통 MP4로 다시 포장, `src/mp4Flatten.ts`). 클래식 소리로 교체. 배경 모델을 `gemini-3.1-flash-lite-image`로(3.1 대비 반값·5~6초) + 제품 클로즈업 프롬프트(폭 75%). 배경 프롬프트 전면 재검토(그릇·케이스는 제품의 일부, 업종별 10세트). 회원가입 코드, 결제 테스트 모드 검토, 기술문서(팀 2장)·기술설계서 통합본(교수 6장).

**10-20** — 결과 화면 재설계(결과가 열리자마자 진짜 영상, 포스터 처음부터 크게, 진행 막대 속도, 다른 채널 문구 25초 대기). UX 점검 반영(내 홍보물 = 한 번 만든 것이 카드 1장). 흩어진 md를 docs/README 하나로 모음. 다른 채널 문구가 안 뜬 원인: Vercel 응답 11초 > 서버 예산 11초 → 20초로. [다른 말로 바꾸기] 없앰(채널마다 문구 1개). 고르기 칩·버튼 모양 통일. `main` 병합.

**10-21** — 쉬운 화면 입력은 키보드가 기본, [말로 하기]를 눌러야 듣기. 포스터 크기 이름 4:5·1:1·9:16(쉬운 화면 1번·2번·3번). 회원가입 설정 끝(카카오 2025 콘솔, KOE205 해결). 영상 6초 → 10초. 자동 채우기가 짧은 문구까지 채움. 결과 화면에서 홈으로·다음 버튼·완료 문구 제거.

**10-22** — 결과 탭 밑줄형 + 회색 세그먼트(고른 칸 남색 + ✓). 포스터는 크기 대신 스타일 1·2·3(4:5 고정, 스타일 3 "사진 카드"). 영상 두 컷(전체 → 상품 클로즈업, 분석 상자 또는 색으로 상품 조준), 제품별 색감, WebCodecs 빠른 MP4. 홈은 상품 사진만 받는 앱으로(예시 카드 9장). 저장: 안드로이드 바로 다운로드, 아이폰 '이미지 저장' 안내, 만든 영상을 폰에 보관해 내 홍보물에서 바로 재생. 기종 11종 점검으로 버그 2개 수정. **기능 고정** 시작. 유료 Gemini 글 모델 실제 확인(3.04원). 발표 준비 문서.

**10-26** — AI 표시 빈틈 수정(사용자 결정, 표시 누락 보완): 보정 사진은 결과 화면 배지만 있고 저장·공유 파일엔 표시가 없었다 → 파일에 포스터와 같은 "AI 활용" 알약(`stampAiMark`, 오른쪽 아래). 이제 포스터·영상·보정 사진 모두 보이는 표시, 홍보 글은 복사·공유 때 "AI가 쓴 글이 들어 있어요" 안내(인공지능기본법 제31조: 실물 같은 이미지는 사람이 보는 표시만 인정, 글은 화면 안내로 충분하다는 해설). 점검 `verify:background`에 저장 파일 표시 확인 추가.
같은 날 실기기 QA: ① 네이버 홍보 글만 끝까지 기본 글 — 지시문 "방문에 필요한 정보"가 "매일 ○시" 같은 운영 정보를 지어내게 해 금지어("매일")에 걸린 것으로 추정(실제 AI 응답은 미확인) → 네이버 지시문에 "방문 정보는 <shop>에 주어진 것만" ② 채널을 바꾼 뒤 AI가 쓰는 동안(최대 25초)에도 "기본 글로 만들었어요"가 떠 실패처럼 보임 → 쓰는 중에는 "글을 쓰고 있어요" ③ 홍보 글 [복사하기] 줄과 아래 메뉴 사이 14px 틈으로 글이 비침 → 줄을 틈까지 내림.
같은 날(사용자 "너무 느리다"): 첫 채널 AI 글이 오면 나머지 두 채널(네이버·당근)을 뒤에서 미리 받아 둔다 → 채널을 눌러도 기다림 없음. 첫 글이 실패하면 미리 받지 않는다. 홍보물 1건에 글 호출이 1회 → 3회(기관 Claude 우선, 유료로 넘어가면 건당 약 3원 × 3). 같은 주소 분당 20회 제한에 3배 빨리 닿으니 발표 날 제한 풀기와 함께 볼 것.
같은 날(사용자 "Vercel 첫 화면이 깨졌다 다시 뜬다"): 원인은 화면 비율 값(`--s`)을 첫 화면을 그린 **뒤에** 재서 1 → 약 1.1로 바뀌며 머리줄·본문·하단바가 한 번 튀던 것(레이아웃 흔들림 0.187). `StudioScreens.tsx` 측정을 `useLayoutEffect`로 옮겨 그리기 전에 잼 → 0. 로고 SVG 미리 받기, 영상용 명조 글꼴 CSS는 첫 화면을 막지 않게. 예시 이미지까지 미리 받으면 느린 망에서 JS가 1.2초 → 2.2초로 늦어져 뺐다.
