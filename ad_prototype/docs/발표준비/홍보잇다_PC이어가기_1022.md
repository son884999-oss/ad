없으면 설치하고, 있으면 버전만 확인한다. 관리자 권한이 필요하면 사용자에게 한 번에 모아서 요청한다.

```powershell
winget install -e --id OpenJS.NodeJS.LTS        # Node 22 이상
winget install -e --id Git.Git
winget install -e --id Gyan.FFmpeg              # 영상 변환
winget install -e --id Python.Python.3.12       # PPT 제작
winget install -e --id VoyagerX.Vrew            # 자막·목소리 (없으면 vrew.ai에서 설치 파일)
pip install python-pptx pywin32 lxml pillow
```

- **발표·영상 도구(모두 앱이 아니라 발표 자료 제작용):**
  - **Slidev**(MIT, 웹 슬라이드): `npm init slidev@latest slides` → `C:\홍보잇다_발표\slides`. 발표는 `npx slidev`(발표자 보기 포함), 백업은 `npx slidev export`(PDF)와 `npx slidev export --format pptx`(장마다 그림, 애니메이션 없음). Mermaid 도식이 내장돼 있다.

  - **아이콘:** Lucide 또는 Tabler Icons(MIT). 폰트 Pretendard(OFL).
  - **내레이션:** Vrew 목소리를 먼저 쓴다. 한국어 품질 비교용으로만 VoiceStudio(AGPL-3.0, 로컬 TTS)를 써 볼 수 있다. 도구로만 쓰고 앱 코드에 넣지 않으며, 고른 음성 모델의 상업 이용 조건을 확인해 출처 파일에 적는다.

## 3. 시연 영상 (Playwright MP4 + 가짜 커서 + Vrew)

### 3-1. 녹화 방식: 실제 AI로 찍는다

가짜 응답으로 찍으면 "진짜 AI냐"는 질문을 막을 수 없고, 잰 시간도 의미가 없다. 그래서 **실제 AI가 연결된 앱**으로 녹화한다.

- 대상(둘 중 하나, 사용자에게 먼저 묻는다)
  1. 배포 사이트 `https://codyssey.vercel.app` (권장, 실제 서비스 그대로)
  2. 로컬 개발 서버(`npm run dev`). 사용자의 `.env.local`에 키가 들어 있어야 한다. Claude는 이 파일을 열지 않는다.
- **예산:** 시작 전에 사용자에게 예산을 묻는다. 기본 제안은 "최대 5번 녹화, 약 500원 이내"다(한 번에 배경 보정 약 50원 + 글·사진 분석). 호출 전에 장부에 적고 커밋한다(0절).
- 녹화 설정: 390×844, `deviceScaleFactor: 2`, `isMobile: true`, `hasTouch: true`, **창이 보이는(headless: false)** Edge로 찍는다. `recordVideo: { dir, size: { width: 780, height: 1688 } }`로 녹화하고, ffmpeg로 바꾼다(H.264, 30fps, `-crf 18`, `-pix_fmt yuv420p`, `-movflags +faststart`).
- 앱 로그인 장면(3-4절 10번)을 위해 앱 녹화도 `launchPersistentContext`(프로필 `C:\홍보잇다_발표\work\app-profile`)로 연다. 녹화 전에 사용자가 그 창에서 시연용 계정으로 한 번 로그인해 둔다(4절과 같은 알림 창).
- 실제 AI라 결과가 매번 다르다. 녹화를 끝낼 때마다 결과 화면을 캡처해 사용자에게 보여 주고 "이 녹화를 쓸까요?"를 묻는다. 마음에 들지 않으면 예산 안에서 다시 찍는다.
- 소요 시간(사진 올리기 → 결과)은 실제 녹화에서 잰 값이다. 사용자 확인 대기 시간은 빼고, 노트에 측정 방법을 적는다.
- **백업:** 발표장 인터넷이나 AI가 실패할 때 쓸 백업판을 하나 더 찍는다. 이 백업판은 가짜 응답(3-2-1절)으로 찍고, 파일 이름에 `_backup`을 붙인다. 슬라이드에 쓸 때는 "저장된 응답으로 재생"이라고 표시한다.

### 3-2. AI가 잘못 알아들으면: 중간에 사람이 고친다

AI 자동 채우기가 끝나면 스크립트가 멈추고 사용자에게 확인을 받는다. 이 장면도 녹화에 남긴다. 실제 사장님이 쓰는 모습과 같기 때문이다.

1. 자동 채우기가 끝나면 채워진 값(제품 이름, 설명, 짧은 문구 등)을 읽는다.
2. Windows 입력 창을 띄운다.
   - 방법: PowerShell `Add-Type -AssemblyName Microsoft.VisualBasic; [Microsoft.VisualBasic.Interaction]::InputBox(...)`
   - 문구: "AI가 '제품 이름'을 'OOO'로 채웠어요. 맞으면 그대로 [확인], 틀리면 고쳐서 [확인]."
   - 값이 여럿이면 칸마다 하나씩 묻는다. 제품 이름, 짧은 문구, 가게 이름, 가격 순서다.
3. 고친 값이 있으면 녹화 화면에서 가짜 커서로 그 칸을 누르고, 지운 뒤 사람 속도(`pressSequentially`, 70ms)로 다시 친다.
4. 사진 분석이 실패하거나 사진 점검에서 경고가 나오면 그 화면도 그대로 녹화한다. 직접 입력으로 이어 간다.

### 3-2-1. 백업판 가짜 응답 (`_backup`만, `page.route("**/api/**")`)

- `/api/analyze-photo`:

### 3-3. 가짜 커서

- `page.addInitScript`로 지름 28px 원형 커서(흰 테두리, 반투명 검정)를 넣는다. `pointer-events:none`, 맨 위 z-index다.
- 클릭할 때는 커서를 0.5초 동안 부드럽게 이동한다. 누르는 순간 커서가 0.85배로 줄고 주황(#c4622d) 물결이 퍼진 뒤 실제 클릭한다.
- 글자는 `pressSequentially(text, { delay: 70 })`로 입력한다.
- 결과 탭마다 2.5~3초 멈춘다. 영상 앞 1.5초와 끝 2초는 정지 화면이다.

### 3-4. 시나리오: 기본 화면으로 시작해 중간에 쉬운 화면으로 (약 2분 30초)

앞부분은 **기본 화면**으로 세련된 디자인을 보여 주고, 글을 읽고 써야 하는 **정보 입력 단계에서 쉬운 화면으로 바꾼다.** 하던 작업이 그대로 이어진 채 글씨와 버튼만 커지는 것을 보여 주는 게 핵심이다. "보기 좋은 디자인"과 "누구나 읽을 수 있는 화면"을 둘 다 챙겼다는 메시지다.

1. **홈(기본 화면, 3초):** 예시 카드를 한 번 넘긴다 → [홍보물 만들기]
2. 사진 `public/assets/reference-fresh/cake.webp` 올리기 → [다음으로]
3. "배경을 광고 사진처럼 바꿀까요?" → [바꾸기] → 보정이 끝나면 "보정 사진"
4. **정보 입력 화면에 들어오면 1초 멈춘 뒤 머리줄의 [쉬운]을 누른다(전환 장면, 5초).**
   - 같은 화면, 같은 내용에서 글씨와 버튼이 커지는 순간을 천천히 보여 준다. 필요하면 영상 편집에서 전후 화면을 0.5초씩 나란히 보여 준다.
   - 내레이션: "글씨가 작다면, 한 번에 크게." 자막: "하던 내용은 그대로"
   - 이어서 [듣기]를 눌러 화면을 읽어 주는 장면(3초, 3-6절 소리 처리)
5. **정보 입력(쉬운 화면):** [자동으로 채워 주기]로 AI가 칸을 채운다. 3-2절대로 사용자가 확인하고, 틀린 칸은 손으로 고친다. 가게 이름 "달빛제과", 가격은 손으로 입력한다. [말로 하기] 버튼은 커서로 가리키기만 하고 누르지 않는다(자막: "말로도 쓸 수 있어요"). → [홍보물 만들기]
6. 만드는 중 화면(진행 막대)은 3초만 보여 주고 나머지는 잘라 낸다. 잘랐다고 자막에 "실제 대기 OO초"로 밝힌다.
7. **결과(쉬운 화면):** 사진 탭 → 포스터(스타일 1→2→3, 각 1.5초) → 영상(재생해서 10초 전체, 앱 소리 포함) → 홍보 글(인스타그램 하나를 보여 주고 [글 복사하기])
8. [폰에 저장]을 누르고 끝.
9. 4절 인스타 게시 장면 15~20초를 이어 붙인다.
10. **로그인·내 홍보물(약 10초):** 메뉴 → 로그인 화면(카카오·Google·이메일, 모두 실제로 됨)을 3초 → 시연용 계정으로 로그인된 상태에서 내 홍보물을 열어 방금 만든 홍보물을 보여 준다. 내레이션: "로그인하면, 만든 홍보물이 계정에 남습니다."
    - 비밀번호는 Claude가 입력하지 않는다. 사용자가 녹화 전에 시연용 계정으로 로그인해 둔다(3-1절).
11. **비용 카드(영상 끝, 4초):** 시연 마지막에 이번 홍보물 1건에 든 비용을 크게 보여 준다. 예시 구성:
    - 배경 바꾸기 AI 약 OO원 / 사진 읽기·글쓰기 AI 약 O.O원 / 포스터·영상 0원 / **합계 약 OO원**
    - 숫자는 지어내지 않는다. 녹화한 그 회차의 실제 호출 기록(`ad_prototype/docs/비용_품질_출처.md` 장부, 앱 서버 하루 장부 값)과 공식 요금표로 계산한다. 무료 경로(기관 Claude, Gemini 무료)로 처리됐으면 그 항목은 0원으로 적고 "무료 경로"라고 표시한다.
    - 계산 방법은 발표자 노트와 부록 A2에 적는다.
12. 사진 올리기부터 결과가 열리기까지 걸린 시간을 실제 녹화에서 잰다(확인 창 대기 시간 제외). 3장 끝과 12장에 쓴다.

- 부록용으로 같은 흐름을 기본 화면만으로 찍은 짧은 판(약 30초, `demo_basic_final.mp4`)을 따로 만든다. 부록 A5에서 두 화면을 비교할 때 쓴다.
- 선택자는 `scripts/verify-*.mjs`의 것을 쓴다. 예: `getByRole("button", { name: /홍보물 만들기/ })`, `#product-photo`, `getByLabel("제품 이름", { exact: true })`, `.details-primary-bar .studio-primary`, `#result-tab-video`, `getByRole("radio", { name: "스타일 2" })`. 쉬운 화면은 버튼 이름이 다를 수 있으니 `src/easyText.ts`의 바뀐 문구를 확인한다.
- 녹화 뒤 ffprobe로 길이와 해상도를 확인하고, 프레임 6장을 뽑아 본다. 흰 화면, 엉뚱한 커서 위치, 오류 문구가 있으면 다시 찍는다.
- 팀 카드용 화면 캡처(사진 입력, 정보 입력, 포스터 3종, 영상 프레임, 홍보 글, 결과 탭)도 이때 찍는다.

### 3-5. Vrew로 AI 내레이션·효과음·자막 (트레일러처럼)

발표용 시연 영상은 **강한 AI 목소리 내레이션 + 효과음 + 큰 자막**으로 만든다. 제품 광고 트레일러 느낌이다. 영상이 도는 2분 동안 발표자는 말하지 않는다.

Vrew는 외부에서 조작할 API가 없다. 그래서 **컴퓨터 사용(computer use)** 으로 Vrew 화면을 조작한다. 컴퓨터 사용을 쓸 수 없으면 대본과 효과음 위치표만 만들고 사용자에게 순서를 안내한다.

1. **내레이션 대본** `demo_narration.txt`
   - 장면별 1문장, 짧고 힘 있게 쓴다. 전체 250~350자, 장면 시작 시각(초)을 같이 적는다.
   - 예: "사진 한 장." / "AI가 배경을 광고 사진으로." / "틀리면, 바로 고치면 됩니다." / "포스터. 영상. 홍보 글까지." / "걸린 시간, OO초."
   - 화면에 실제로 나오는 것만 말한다. 없는 기능을 말하거나 과장하지 않는다("세계 최초", "완벽한" 같은 말 금지).
2. **목소리:** Vrew AI 목소리 중 또렷하고 힘 있는 성인 목소리 하나(광고·예고편 톤). 속도는 보통보다 조금 빠르게 한다. 장면 전환 직전에 문장이 끝나게 맞춘다.
3. **효과음:** 장면 전환(휙), 버튼 누름(딸깍), 결과가 나올 때(짠) 세 종류만 쓴다. Vrew 기본 효과음이나 라이선스가 분명한 무료 효과음만 쓰고, 출처를 `C:\홍보잇다_발표\효과음_출처.txt`에 적는다. 앱 영상 탭이 재생되는 10초 동안은 효과음을 넣지 않고 앱 원래 소리를 살린다.
4. **배경음:** 앱의 클래식 배경음은 시연용으로 너무 잔잔하니 쓰지 않는다. 박자가 분명하고 밝은 곡을 쓴다.
   - 찾는 곳(순서대로): Vrew 기본 배경음 → Pixabay Music(출처 표기 없이 상업 이용 가능, 받을 때 페이지의 라이선스 문구를 다시 확인) → YouTube 오디오 보관함(곡마다 저작자 표시 필요 여부 확인)
   - 검색어 예: "upbeat", "energetic", "trailer", "hype", "corporate upbeat", 90~120초 길이
   - 곡을 2~3개 골라 30초씩 들어 볼 수 있게 사용자에게 먼저 보여 주고, 고른 곡을 쓴다.
   - 볼륨은 내레이션보다 -12~-15dB. 첫 3초는 크게 시작하고, 내레이션이 나오면 줄이고(덕킹), 마지막 결과 장면에서 다시 올린다.
   - 앱 영상 탭이 재생되는 10초 동안은 배경음을 끄고 앱 원래 소리를 들려준다.
   - 출처와 라이선스는 `효과음_출처.txt`에 같이 적는다.
   - 효과음도 같은 곳에서 고른다. Kenney UI Audio(CC0)도 쓸 수 있다.
5. **자막:** 내레이션과 같은 문장을 크게(화면 폭의 6% 이상), 흰 글자에 검정 띠로 넣는다. 앱 버튼을 가리지 않게 화면 위쪽이나 옆에 둔다.
6. **내보내기:** MP4(1080p) → `demo_final.mp4`. 기본 화면판도 같은 방식으로 → `demo_basic_final.mp4`.
7. 타임라인 위치 조정이 3번 넘게 실패하면 멈추고, 남은 작업을 사용자에게 넘긴다.
8. 발표장 스피커가 안 될 때를 대비해, 자막만으로도 이해되는지 소리 없이 한 번 재생해 본다.

### 3-6. 소리 처리 (Playwright 녹화에는 소리가 없다)

Playwright의 `recordVideo`는 화면만 찍고 소리는 담지 않는다. 그래서 앱 소리는 따로 넣는다.

- **앱 영상 탭 소리:** 녹화 중 앱에서 저장한 영상 MP4의 소리를 ffmpeg로 꺼내서, 영상 탭 재생이 시작된 시각에 맞춰 넣는다. 재생 버튼을 누른 시각은 녹화 스크립트에서 기록한다.
- **[듣기] 소리:** 둘 중 하나를 고른다.
  1. Windows 소리를 같이 녹음한다(ffmpeg `-f dshow -i audio="스테레오 믹스"` 또는 WASAPI 루프백). 스테레오 믹스가 꺼져 있으면 사용자에게 켜 달라고 요청한다.
  2. 안 되면 [듣기]를 누른 장면에 자막 "화면을 소리로 읽어 줍니다"만 넣는다.
- 이 소리 처리는 Vrew 작업(3-5절) **전에** 한다. 내레이션과 배경음은 앱 소리 구간에서 낮춘다.

**녹화**
6. 1280×860으로 녹화하고, 가짜 커서를 넣는다. 왼쪽에는 앱(폰 크기), 오른쪽에는 인스타 웹을 둔다. 한 번에 찍기 어려우면 두 장면을 따로 찍어 ffmpeg로 잇는다.
7. 흐름: 앱 [저장] → 인스타 [만들기] → 파일 넣기 → [다음] → [다음] → 캡션에 홍보 글 붙여 넣기
8. **[공유하기] 직전에 멈추고 확인 창을 띄운다.** "지금 이 계정에 실제로 게시합니다. 진행할까요?"
   - [예]: 게시하고, 완료 화면과 프로필의 게시물을 3초 보여 준다.
   - [아니요]: 그 화면에서 녹화를 끝낸다.
9. MP4로 바꾸고, 3-5절처럼 자막과 목소리를 넣는다 → `demo_instagram_final.mp4`
10. 시연 게시물은 Claude가 지우지 않는다. 지울지는 사용자가 정한다.

**막힐 때**
- 선택자는 `getByRole`과 화면 글자("만들기", "다음", "공유하기")로 찾는다.
- 3번 실패하면 멈추고 어느 단계에서 막혔는지 보고한다.
- 대체안: 사용자가 폰에서 [보내기] → 인스타 게시를 직접 화면 녹화하고, 그 파일에 자막과 목소리만 넣는다.

## 5. 슬라이드 디자인

**본 발표는 Slidev 웹 슬라이드로 브라우저에서 한다.** 발표장 PC에서 브라우저 발표가 된다(사용자 확인). 애니메이션·영상 넣기·도식이 PowerPoint보다 자유롭다. 백업으로 PDF와 PPTX(그림판)를 같이 만든다. 아래 디자인 규칙은 Slidev에도 그대로 적용한다.

공통:
- 16:9, Pretendard. 앱 색 토큰을 쓴다(주황 #c4622d, 짙은 갈색 #3d1d0c, 크림 #fdf3ea, 남색 #24395c).
- **AI가 만든 PPT 티를 피하는 규칙**
  - 슬라이드마다 구도를 바꾼다. "제목 + 글머리 3개" 배치를 반복하지 않는다.
  - 글머리 목록은 2장 이하로 쓴다. 나머지는 큰 숫자, 실제 화면, 도식, 한 문장으로 채운다.
  - 이모지, 그라데이션 배경, 아이콘 나열, 둥근 카드 반복을 쓰지 않는다.
  - "혁신적인", "획기적인", "~를 통해" 같은 말을 쓰지 않는다. 짧은 사람 말투로 쓴다.
  - 실제 앱 화면과 실제 결과물(포스터, 영상 프레임)을 많이 쓴다.
  - 슬라이드 번호와 출처는 작게, 늘 같은 위치에 둔다.

**버전 A — 잡지·에디토리얼**
- 풀블리드 사진, 80~120pt 제목, 넓은 여백, 비대칭 그리드, 사진 위에 글자를 겹친다.
- 숫자 장(4~6)은 숫자 하나가 화면 절반을 차지하게 한다.

**버전 B — 골목 가게 감성**
- 크라프트지·영수증 질감을 쓴다. 질감은 Python(Pillow)으로 직접 만든다.
- 통계 장은 영수증 모양으로 만든다(품목 = 통계, 합계 = 메시지). 팀 장은 직원 명찰 6개로 만든다.
- 손글씨는 강조 단어에만 쓴다. 감성은 소재로만 내고, 글 내용은 A와 같다.

## 6. 애니메이션과 전환

### 6-1. 방법 (Slidev)

- 요소 등장은 `v-click`, 장면 사이 이동은 `transition`(fade, slide-left 등)과 `v-motion`(위치·크기 이동)으로 한다. 모핑처럼 같은 요소가 장을 넘어 이어지는 효과는 Slidev의 Magic Move(코드) 또는 같은 위치의 요소를 `v-motion`으로 맞춰 흉내 낸다.
- 시연 영상은 `<video>`로 넣고 클릭하면 재생되게 한다. HyperFrames로 만든 카드 영상도 같은 방식으로 넣는다.
- 발표자 노트는 각 장 아래 `<!-- -->` 주석에 쓴다(발표자 보기에서 보임).
- 백업용 PPTX를 PowerPoint 애니메이션까지 살려 따로 만들 필요는 없다. 시간이 남으면 python-pptx + PowerPoint 자동 조작(win32com)으로 만든다.

### 6-2. 장별 연출 (애니메이션은 최대 6장, 한 장 클릭은 2번 이하)

| 장 | 연출 |
|---|---|
| 1 | 결과물 사진이 천천히 확대되며 등장, 제목은 단어별로 올라옴 |
| 2 | 결과물 3개가 사진 한 장에서 펼쳐짐(이동 경로 + 확대) |
| 3 | 영상 클릭 재생. 끝나면 소요 시간 숫자가 확대 등장 |
| 4 | 그래프가 왼쪽에서 닦아 내듯 등장, 50대·60대 막대 Pulse |
| 8 | 사진 → 장면표 → 300장 → MP4 순서로 하나씩 Fade |
| 12 | 모핑: 결과물 3종이 한 화면에 모이고 소요 시간 숫자가 커짐 |

- 나머지 장은 Fade 전환만 쓴다. 숫자 카운트업은 쓰지 않는다.
- 서로 다른 지표를 하나로 이어 보이게 하는 모핑(예: 82.0% → 45.6%)은 쓰지 않는다.
- 효과 하나는 0.4~0.8초로 한다. 부록에는 애니메이션을 넣지 않는다.

## 9. Q&A 방어

### 9-1. 답변 원칙 (`QnA_방어.md` 맨 위)

1. 결론 먼저, 근거 하나, 한계 인정. 30초 안에 답한다.
2. 모르면 "지금은 확인하지 못했습니다. 이렇게 확인하겠습니다"라고 말한다. 지어내지 않는다.
3. 공격성 질문은 한 문장으로 다시 정리한 뒤 답한다.
4. 숫자 질문에는 해당 부록을 바로 띄운다.
5. "AI 쓰면 다 되는 거 아니냐"에는 "AI를 어디에 쓰고 어디에 안 쓰는지가 설계의 핵심"으로 답한다.
6. 심사위원이 비전공자·공무원이므로 답은 쉬운 말로 한다. 기술 질문에도 먼저 "사장님 입장에서는~"으로 효과를 말하고, 원리는 그다음 한 문장만 말한다.

### 9-5. Q&A 라이브 시연: 말로 하기

- 발표 전에 폰으로 배포 사이트를 열어 쉬운 화면, 정보 입력 단계까지 진행해 둔다(사진은 미리 올려 둠). 마이크 권한도 미리 허용한다.
- 폰 화면을 발표장 화면에 띄울 방법을 미리 정한다(화면 미러링·USB 연결 등). 안 되면 폰을 들고 심사위원 쪽으로 보여 준다.
- 순서: [말로 하기] → "달빛제과" 또는 "초코 생크림 케이크"라고 말함 → 칸에 들어가는 것을 보여 줌. 10초 안에 끝낸다.
- 실패 대비: 발표장 소음으로 인식이 안 되면 "조용한 곳에서는 이렇게 됩니다"라며 미리 폰으로 찍어 둔 10초 화면 녹화(`voice_backup.mp4`, 사용자가 직접 찍음)를 부록 A5에서 튼다.
- 부록 지도(`부록지도.pdf`)에 "말로 입력? → 폰 라이브 / A5 백업"을 적는다.

## 10. 마지막 확인

1. 만든 시연 영상을 모두 처음·중간·끝으로 재생해 목소리·효과음·자막이 장면과 맞는지 본다.
2. Slidev를 PDF로 내보내 장마다 확인한다(또는 브라우저에서 장마다 캡처). 겹침, 잘림, 넘친 글자, 빈 칸을 고친다. 발표장과 같은 해상도(1920×1080)로 본다.
3. `npx slidev`로 처음부터 끝까지 넘겨 본다. 클릭 순서, 영상 재생(소리 포함), 부록 링크, 발표자 보기를 확인한다. 인터넷 없이도 열리는지(글꼴·영상이 로컬 파일인지) 확인한다.
4. 모든 수치를 2-3절 표와 대조한다. 출처가 없는 숫자는 지운다.
5. 발표자 노트 분량 + 시연 영상 길이로 9분~9분 40초인지 계산한다.
6. QR을 실제 폰 2대(안드로이드, 아이폰) 카메라로 찍어 배포 사이트가 바로 열리는지 확인한다. 화면에 띄운 크기와 인쇄한 크기 둘 다 확인한다.
7. 발표장 대비로 Slidev를 정적 사이트로 빌드한 것(`npx slidev build`, `dist/` 폴더), PDF·PPTX 백업과 `부록지도.pdf`, `QR_안내지.pdf`, 영상 파일을 `C:\홍보잇다_발표\USB\`에 따로 모은다.
8. 결과물 목록(파일, 크기, 장 수, 영상 길이)과 사용자가 직접 할 일을 보고한다.
