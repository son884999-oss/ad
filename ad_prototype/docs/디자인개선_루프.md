# 품질 개선 루프

`/loop`로 계속 돌리는 품질 개선 작업의 명령어, 채점 기준, 기록입니다. 화면 디자인뿐 아니라 홍보 글·포스터·영상 품질까지 다룹니다. 모바일 웹앱만 다룹니다(PC는 휴대폰 틀).

## 실행 명령어

Claude Code에 아래를 그대로 붙여 넣습니다. 간격 없이 쓰면 스스로 속도를 정해 반복합니다. 멈추려면 Esc를 누르거나 "루프 멈춰"라고 말합니다.

```
/loop 홍보잇다 모바일 웹앱(C:\Users\82104\Desktop\ad\ad_prototype, 브랜치 feature/UI-Screen)의 품질을 한 바퀴에 하나씩 올린다. 먼저 docs/자동작업_프롬프트.md 의 진행 규칙과 docs/디자인개선_루프.md 전체(채점 기준, 호출 한도, 기록)를 읽고 그대로 따른다. 영상 유료 호출 한도는 이 문서가 우선한다. 한 바퀴: (1) 기록의 "다음 영역"을 고른다. (2) 그 영역을 문서의 채점 기준으로 지금 점수를 매기고 근거를 적는다. (3) 점수를 가장 많이 올릴 문제 1개를 골라 ad_prototype 안에서 고친다. 이미 기록에 있는 변경을 되돌리거나 같은 곳을 다시 만지지 않는다. (4) npx tsc --noEmit -p . , npm run -s build, verify:easy·photo·records·video·ai·promo, verify-reference-rebuild, npm run audit:screens(문제 0개)가 모두 통과해야 한다. (5) 같은 기준으로 다시 채점하고, 점수가 오르지 않았으면 변경을 버린다. (6) 올랐으면 커밋하고 origin/feature/UI-Screen 에 푸시한 뒤, 기록 표에 한 줄(날짜·영역·전→후 점수·고친 것·커밋)을 추가하고, 점수판과 호출 사용량을 갱신하고, "다음 영역"을 바꾼다. 모든 영역이 90점 이상인 상태로 한 바퀴를 다 돌면 루프를 멈추고 결과와 남은 큰 일을 보고한다.
```

## 영역과 채점 기준 (각 100점, 목표 90점)

점수는 측정값을 먼저 쓰고, 눈으로 보는 부분은 아래 감점표를 그대로 적용합니다. 점수를 올려 적지 않습니다. 근거가 없는 항목은 감점된 채로 둡니다.

## 영역 순서

1. 홍보 글 → 2. 포스터 → 3. 영상 → 4. 화면 디자인(홈 → 사진 → 내용 → 결과 → 메뉴 → 내 홍보물 → 로그인 순으로 한 바퀴에 한 화면) → 다시 1번

90점을 넘은 영역은 건너뛰고, 점수가 가장 낮은 영역을 먼저 합니다.

## 호출 한도 (루프 전체 합계)

| 호출 | 한도 | 규칙 |
|---|---|---|
| Higgsfield 실제 영상 (유료, 1건 약 $0.21~0.31) | **루프 전체에서 최대 2번** | 영상 프롬프트(`api/_lib/video-prompt.js`)를 고친 뒤, 무료 점검을 다 통과했을 때만 씁니다. 한 번 쓰기 전에 아래 사용량을 먼저 1 올려 커밋합니다(중간에 멈춰도 한도를 넘지 않게). 2번을 다 쓰면 영상은 무료 점검만 합니다. 실패해도 다시 시도하지 않습니다. |
| Gemini 실제 호출 (무료 키) | 한 바퀴에 최대 6번, **하루 20번이 키 전체 한도** | 홍보 글 채점과 사진 분석 확인에만 씁니다. 429 `PerDay` 응답이면 그날은 홍보 글 바퀴를 건너뛰고 다음 영역으로 갑니다(응답의 retryDelay 뒤 다시). |
| `VIDEO_ENABLED` | 켜지 않음 | `.env.local`과 Vercel 설정은 건드리지 않습니다. 유료 테스트는 스크립트로만 합니다. |

## 판단 기준

- 고령 사용자에게 쉬운 쪽: 더 큰 글씨, 더 적은 선택지, 한 화면에 한 가지 일.
- 한 화면에 주황색 주 버튼은 하나만 둡니다.
- 글자 14px 이상, 대비 4.5:1 이상, 누르는 곳 44px 이상(쉬운 화면 52px 이상).
- 새 색·새 글꼴·새 npm 패키지를 들이지 않습니다.
- 기능을 없애거나 흐름을 바꾸는 큰 변경, 비용이 드는 변경은 하지 않고 [품질개선_로드맵.md](품질개선_로드맵.md)에 적습니다.
