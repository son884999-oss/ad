# 홍보잇다 Phase 2 — 브랜드와 디자인 시스템

후속 변경: 사용자가 C안 ‘오가는 흐름’을 선택함에 따라 현재 로고·색상 기준은 [선택 브랜드 사용 기준](public/assets/branding/selected/BRAND_GUIDE.md)과 `src/design-tokens.css`를 따른다. 아래는 Phase 2 당시의 기록이다.

## 브랜드 원칙
공식 이름은 **홍보잇다**다. 홈페이지·메뉴·로그인 체험·푸터·브라우저 title·description·Open Graph에 같은 이름을 사용한다. 기존 연결을 뜻하는 ∞ 모양을 짙은 세이지 바탕의 간결한 기호로 정리했다. 독립적인 새 브랜드명을 만들지 않았다.

브랜드 약속: **사장님의 정성을, 더 많은 손님에게.**
핵심 행동: **홍보물 만들기**.
소개 문구: **우리 가게 홍보, 사진 한 장으로 시작해요.**
‘AI가 모든 것을 완성한다’는 미구현 약속 대신 현재 예시 결과 체험임을 명시한다.

Phase 1의 시니어 UX, frontend, 디자인 디렉터 검토를 다음처럼 구현했다.
- UX: 첫 화면에서 바로 시작, 가입 없이 체험, 선택 사항인 채널, 동작을 설명하는 한국어, 결과에서 저장 후 할 일까지 안내.
- frontend: 기존 출력·복원 로직 유지, 채널 설정 분리, native radio, 토큰 중심 CSS, 같은 글꼴을 화면과 Canvas에서 참조.
- 디자인: 아이보리 바탕과 남색 본문, 세이지 행동, 민트·피치·하늘색의 절제된 면. 동일 인물의 원본 일러스트로 도구와 사용자의 관계를 설명.

## 색상과 의미
실제 값은 `src/design-tokens.css`가 기준이다. 파스텔 글자를 흰색 바탕에 얹지 않는다.

| 토큰 | 값 | 용도 |
|---|---|---|
| color-canvas | #FAF9F5 | 전체 배경 |
| color-surface | #FFFFFF | 카드·입력면 |
| color-ink | #20324A | 본문·제목 |
| color-muted | #526176 | 보조 설명 |
| color-brand / hover | #28594E / #1D443B | 주요 행동·선택 |
| color-mint | #DCEDE3 | 선택·성공 배경 |
| color-peach | #F4D8C6 | 이미지 만들기 안내 |
| color-sky | #DCE8F5 | 글·정보 안내 |
| color-control | #74877E | 입력·선택 경계 |
| color-focus | #255C9A | 3px 키보드 포커스 |
| color-error / soft | #963B32 / #FBECE8 | 오류 표현 |

글자와 배경의 주요 6개 조합은 자동 대비 계산에서 4.5:1 이상이어야 한다. 카드의 장식 테두리와 조작 가능한 입력 테두리를 구분한다. 전체 WCAG 적합성 인증을 받았다는 의미는 아니다.

## 글꼴·간격·형태
- `Noto Sans KR` 가변 글꼴 100–900, `Malgun Gothic`, sans-serif 순서. 기존 Figma 폰트 URL을 유지하되 font-family 별칭 중복을 없앴다. `font-display: swap` 적용. 원격 폰트 실패 시 시스템 글꼴로 작동한다.
- 일반 본문 18px/1.65, 기본 켜짐인 간편모드 주요 본문 22px/1.65, 보조 설명 최소 16px.
- 모바일 제목 약 29–34px, 넓은 화면 hero 최대 46px. 한국어는 단어 단위로 줄바꿈하고 긴 무공백 문자열은 넘침 없이 분리.
- 간격 4/8/12/16/24/32/48px. 카드 안 20–24px, 큰 섹션 28–48px.
- 입력·버튼 radius 12px, 카드 20px, 대표 섹션 28px.
- 기본 행동 52px 이상, 간편모드 버튼 60px 이상. native radio 자체는 22px이나 선택 영역 전체가 84px 이상인 label이다.
- 굵기·문구·체크/선택 표기를 함께 사용해 색상에만 의존하지 않는다.

## 공통 구성 요소
| 요소 | 구현 규칙 |
|---|---|
| 주요 버튼 | 짙은 세이지/흰 글자, 한 구간의 대표 행동에 사용. disabled는 실제 disabled와 색상 변화 함께 적용 |
| 보조 버튼 | 흰 바탕/진한 테두리, 수정·돌아가기·외부 서비스 열기 |
| 글자 버튼·링크 | 명확한 동사, 링크는 용도와 새 창 여부 표시 |
| 입력 | 외부 label·도움말·오류 설명. placeholder만으로 의미를 전달하지 않음 |
| 채널 선택 | fieldset/legend/native radio, 선택 표시, 한 문장 설명, 기타 채널 점진 노출 |
| 업종 추천 | 선택 사항인 native select. 추천 순서만 바꾸고 현재 선택값을 변경하지 않음 |
| 모바일 메뉴 | dialog, focus trap, Escape 닫기, 닫힌 후 포커스 복원, 배경 inert 유지 |
| 결과 카드 | 원문 확인, 미리보기, 저장 행동을 구분. 데이터 개수별 grid 유지 |
| 결과 활용 안내 | 저장 다음 단계에서 수동 업로드 설명. 외부 링크를 자동 게시 버튼으로 부르지 않음 |
| 빈 기록 | 사진 안내 일러스트, 비어 있는 이유, ‘첫 홍보물 만들기’ 버튼 |
| 사진 확인 중 | aria-busy와 상태 문구, 다음 단계 비활성화, 기존 사진 보존 |
| 영상 준비 중 | 기존 준비·취소·실패·미지원 상태와 재시도 보존 |
| 성공·오류 | 확인 가능한 결과와 다음 행동 안내. 메시지만 바꾸고 실제 상태를 숨기지 않음 |

이미 있던 파일·복사·음성 오류 상태는 기능을 유지했다. Phase 2에서 존재하지 않는 AI 처리 대기 화면을 연출하지 않는다.

## 반응형 규칙
- 320px부터 단일 열. 시작 버튼이 긴 안내·일러스트보다 먼저 나온다.
- 768px부터 hero와 안내 카드를 공간에 맞게 분할. 채널 기본 추천 3열, 추가 채널 2열.
- 1024px부터 좌측 작업 메뉴 232px, 모바일 하단 메뉴를 숨김.
- 결과 카드는 1440px 이상에서 3개/2개 결과 수에 맞는 열 수, 그 아래 1열. 기존 해결된 레이아웃을 그대로 보존.
- 작은 화면 입력 중에는 하단 내비게이션을 숨기고 설명 단계의 다음 버튼은 문서 흐름에 둔다. 낮은 높이에서는 고정 헤더·하단 버튼을 해제한다.
- `prefers-reduced-motion` 환경에서 전환·애니메이션 최소화.
- 실제 200% 브라우저 확대와 무공백 한글·이모지·긴 설명을 검증한다.

## 일러스트 제작과 사용
공식 `imagegen` 스킬의 **내장 image_gen 도구 모드**로 실제 4종 생성. CLI/API fallback과 유료 외부 API를 사용하지 않았다. 첫 hero를 이후 3장에 스타일·인물 참조로 전달했다. 복제한 외부 사이트 일러스트는 없다.

| 파일 | 적용 위치 | 배포 크기 | 모바일 |
|---|---|---|---|
| shop-marketing-hero.webp | 홈페이지 대표 장면 | 960×640 | 640×427 srcset, 높이 최대 230px |
| step-photo.webp | 1단계 설명·빈 기록 | 400×400 | 안내 96px, 빈 기록 160px |
| step-details.webp | 2단계 설명 | 400×400 | 안내 96px |
| step-ready.webp | 3단계 설명·결과 요약 | 400×400 | 안내 96px, 결과 56–88px |

성인 가게 운영자, 얇은 남색 윤곽선, 민트 앞치마·하늘색 셔츠, 제품 사진→글→저장이라는 동일한 서사를 사용한다. 실제 파일은 flat vector **스타일의 raster**이며 편집 가능한 SVG로 오인하지 않는다. 그림 안 문구는 넣지 않고 화면에서 한국어로 표시한다. 장면에는 소량의 색면 음영이 있으나 3D·사진·배경 장식을 사용하지 않았다.

원본: `design-assets/illustrations/*.png`.
배포: `public/assets/illustrations/*.webp`.
최종 프롬프트: `design-assets/illustrations/prompts.json`.
크기/용량: `public/assets/illustrations/asset-manifest.json`.
재최적화: `node scripts/optimize-illustrations.mjs`. 기존 Playwright의 이미지 인코더로 크기·포맷만 바꾸고 투명 alpha를 보존한다. 새 runtime 패키지는 추가하지 않았다.

hero는 장면을 설명하는 alt를 사용하고, 단계·결과 이미지는 옆의 동일한 설명을 반복하지 않도록 `alt=""`로 처리한다. 하단 단계 이미지는 lazy loading, hero는 fetchPriority high와 고정 비율을 사용한다. 원본 PNG는 배포 public 밖에 보관한다.

## 다음 구현자가 지킬 기준
새 화면은 정확한 브랜드명과 위 토큰을 사용한다. 현재 2,000줄 이상인 App의 출력·미디어 로직은 Phase 3에서 역할별 hook/service로 분리하되 기존 회귀 테스트를 먼저 유지한다. 새로운 생성 서버·로그인 서버·결제·자동 게시를 구현하지 않고 작동한다고 표시해서는 안 된다. 실제 영상 규격·파일 저장·지속 기록을 검증한 뒤 배포 범위를 확대한다.
