## A. 발표 뒤 바로

### [점검정비] 점검 스크립트를 지금 흐름에 맞추기
- `verify:records`가 포스터 미리보기를 기다리다 시간 초과(10-22 이전부터). 배경 팝업 흐름을 못 따라가는 것으로 보임, 앱 고장 아님.
- `audit:screens`가 10-20의 0개에서 762개로. 대부분 헤드리스 "초점 테두리 없음"과 의도한 홈 예시 가로 넘침 → 판정 기준을 고치고 진짜 문제만 남긴다.
- `verify:ai`·`verify:video` 시간 초과 2건(10-21) 원인 확인.

### [용어통일] 버튼 이름·용어 맞추기
- 10-22에 사진 탭만 맞췄다. 나머지 화면의 같은 동작 이름을 하나로("보정" 용어 포함).

### [일관성] 남은 UI 일관성 항목
- 주 버튼 높이 두 단계(기본 54 / 쉬운 64), 안내 글씨 4~5단계 → 3단계, 메뉴 행 모양, 하단 탭 선택 표시, "사진 바꾸기" 버튼 두 화면 모양, 쉬운 화면 "더 쓰기" 안쪽 글씨 배율.
- 원칙: 같은 종류의 선택은 어느 화면에서나 같은 모양·위치·선택 표시, 같은 말은 같은 뜻.

### [장부서버] 유료 하루 장부를 서버 공용 저장소로
- 지금은 Vercel 서버 메모리라 인스턴스가 여러 개 뜨거나 다시 켜지면 0부터 센다. Supabase 표(또는 Upstash Redis)로 옮긴다.
- 정할 것: 기능 고정 범위인지(사용자).

### [실기기확인] 실제 폰에서만 확인되는 것
- WebCodecs 빠른 MP4 경로, 느린 기기 실시간 녹화가 10초보다 짧게 나오는 문제(헤드리스 약 6.7초), 음성 인식(크롬·삼성 인터넷), 카카오톡 인앱 브라우저, 안드로이드 저장이 갤러리로 가는지, 아이폰 저장 안내.
- 실제 AI의 짧은 문구 품질, 실제 배경 보정에서 재료가 바뀌는지(가짜 응답 투어의 "딸기"는 데모 사진 때문).

### [사진입력화면] 카메라/앨범 두 칸 → 하나로?
- 사용자 의견: 큰 칸 하나가 두 개로 나뉘어 보기 어렵다. **논의 후 결정.**
- 조사(web.dev·MDN·GOV.UK·Ontario): `input accept="image/*"` 하나면 OS가 카메라·앨범 선택창을 띄움. `capture`는 호환성 제한.
- A안(추천): 큰 버튼 하나 "사진 넣기 — 찍거나 앨범에서 고르세요". B안: 큰 [카메라로 찍기] + 작은 "앨범에서 고르기" 링크. iOS Safari·카카오톡 인앱은 실기기 확인.

### [포스터-잘림] 배경 바뀐 사진에서 키 큰 제품 윗부분이 잘리는지 다시 확인
- 10-19 발견(샴푸 병 펌프). 10-22 포스터 스타일 개편 뒤 남아 있는지 확인. 위치 `src/poster/posterRenderer.ts` 사진 자르기.

## B. 영상 품질 (비용 0원, 10-22 검토)

대상 `src/motionVideo.ts`. 이미 기각된 것(입체 효과, 끝 정보 카드, 과한 효과)은 넣지 않는다.

| 순위 | 방안 | 상태·메모 |
|---|---|---|
| A | 원본 + 보정 사진을 서로 다른 컷으로(보정본 전체 컷, 원본 클로즈업) | 할 일. 두 사진 색감을 같게 맞춤 |
| B | 상품 위치 찾아 클로즈업 조준 | **10-22 반영**(분석 상자, 없으면 색으로 추정) |
| C | 느린 기기 녹화 길이 | [실기기확인] 먼저. 그리는 시각을 실제 경과 시간으로, 저사양은 효과 끄고 720×1280 |
| D | 첫 0.6초 훅(1.15배에서 툭 당기며 제품 이름) | 작은 다듬기 |
| E | 컷을 배경음 박자에 맞추기(±0.2초) | 곡별 BPM 기록 필요 |
| F | 포스터 스타일과 영상 마지막 화면 맞추기 | 팀 상의 |
| G | 사진 2~3장 받기(진짜 여러 장면) | 효과 가장 큼, 입력 흐름이 바뀜. 팀 결정 |

측정: `eval:video`에 클로즈업 상품 비율, 실제 길이와 10초 차이, 컷과 박자 차이를 추가.

## 폐기 (다시 꺼내지 않음)

담당 교수에게 "기능을 늘리지 말라"는 확언을 받아 폐기했다(2026-10-22). 문서·발표에 "보류"나 "향후 계획"으로도 쓰지 않는다.

- **[기본형/고급형]** 사진 단계의 기본형/고급형 선택. 10-19 C안 때 화면에서 없앴고, 지금은 영상이 하나뿐이다.
- **[특급]** 결과 화면 "✦ 특급 영상으로 다시 만들기"(Higgsfield 콘셉트 영상, 시연 코드 기기만)와 [특급-품질] 프롬프트 다듬기.
- **[PC화면]** PC 전용 화면. PC는 지금처럼 휴대폰 틀 안에 모바일 화면을 보여 준다. 옛 계획은 [archive/옛문서_1022/pc-redesign-plan.md](archive/옛문서_1022/pc-redesign-plan.md).
- **[결제]** 결제 모듈 구현과 테스트 결제 연결(발표 전까지 하지 않음). 코드는 만든 적 없음. 발표에서는 "회원가입·계정별 저장·비용 장부가 있어 이용권 결제를 붙일 수 있는 구조"까지만 말한다(부록 A12, Q&A 13). 검토 메모는 [archive/옛문서_1022/나중에_할일_1020판.md](archive/옛문서_1022/나중에_할일_1020판.md) [결제] 항목.
- 남은 코드: 숨긴 화면(`?premiumui`, `src/App.tsx` `premiumUi`), `api/video-*`·`api/scene-*`, `api/_lib/higgsfield.js`·`video-prompt.js`·`paid.js`, `src/videoCaptioner.ts`·`src/premiumAccess.ts`. 기능 고정 기간이라 지우지 않았다. 발표 뒤 코드에서 걷어낼지는 따로 정한다.
