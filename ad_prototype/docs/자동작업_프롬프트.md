# 자동 작업 프롬프트 (모바일 웹앱 완성)

사용자가 자리를 비운 동안 Claude Code가 혼자 작업을 이어 가도록 만든 프롬프트입니다.
아래 "명령어" 블록을 Claude Code 입력창에 그대로 붙여 넣으면 됩니다. 판단이 필요한 부분은 "미리 승인한 결정"에 모두 정해 두었습니다.

## 명령어

```
/goal 홍보잇다 모바일 웹앱(C:\Users\82104\Desktop\ad\ad_prototype, 브랜치 feature/UI-Screen)을 아래 계획대로 완성한다. 완료 조건: (1) 1단계 "모바일 전용 전환"이 끝나 개발자 모드 툴바·메뉴의 화면 크기 바꾸기·PC 레이아웃이 사라지고, PC에서는 항상 휴대폰 틀 안의 모바일 화면이 보인다. (2) 2~4단계 작업 목록이 모두 끝났거나, 끝내지 못한 항목마다 막힌 이유가 docs/진척사항_2026-10-17.md에 적혀 있다. (3) npx tsc --noEmit -p . 와 npm run -s build, 그리고 package.json의 verify:easy · verify:photo · verify:records · verify:video · verify:ai · verify:promo, node scripts/verify-reference-rebuild.mjs 가 모두 통과한다(모바일 전용에 맞게 고친 기준으로). (4) 360×740 · 390×844 · 430×932 와 PC 휴대폰 틀(1440×900)에서 기본·쉬운 화면 캡처를 직접 보고 겹침·잘림·가로 스크롤이 없다. (5) 모든 변경이 커밋되어 origin/feature/UI-Screen 에 푸시되어 있다. 진행 규칙과 미리 승인한 결정은 docs/자동작업_프롬프트.md 를 먼저 읽고 그대로 따른다.
```

사용량 한도에 걸려 중간에 멈추면, 다시 시작할 때 같은 명령어를 붙여 넣으면 됩니다. 진척 문서를 보고 이어서 합니다.

반복 실행이 필요하면 `/goal` 대신 아래처럼 써도 됩니다(스스로 간격을 정해 반복).

```
/loop docs/자동작업_프롬프트.md 를 읽고, 남은 작업 중 가장 위 항목 하나를 끝까지 처리한 뒤 검증·커밋·푸시하고 진척 문서를 갱신한다. 모두 끝났으면 루프를 멈춘다.
```

## 진행 규칙 (반드시 지킴)

### 안전·비용
- **유료 호출 금지.** `VIDEO_ENABLED`를 켜지 않습니다. `scripts/live-video-test.mjs`도 실행하지 않습니다. 개발 서버에는 실제 키가 들어 있으므로, 브라우저 테스트는 어떤 것이든 먼저 `**/api/**` 전체를 가짜 응답으로 막고 시작합니다.
- **Gemini 실제 호출(무료 키)은 작업 하나당 최대 3번까지만** 품질 확인용으로 씁니다. 사진 분석과 홍보 글만 보내고, 영상 요청은 막습니다.
- `.env.local`은 읽거나 출력하지 않고 커밋하지 않습니다.
- 팀 폴더 `A_*`~`F_*`는 읽기만 합니다. `ad_prototype/` 안만 고칩니다.
- `main` 브랜치에 머지하지 않고, Vercel 설정도 바꾸지 않습니다. 푸시는 `feature/UI-Screen`에만 합니다.
- 새 npm 패키지는 아래 "미리 승인한 결정"에 적힌 것만 설치합니다.

### 작업 방식
- 한 번에 작업 하나씩 진행합니다: 읽기 → 고치기 → 검증 → 캡처 확인 → 커밋 → 푸시 → 진척 문서 갱신.
- 커밋 메시지는 영어 요약 한 줄과 본문으로 쓰고, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙입니다.
- 검증이 실패하면 원인을 찾아 고칩니다. 테스트가 바뀐 설계와 맞지 않을 때만 테스트를 고치고, 그 이유를 커밋 본문에 적습니다. 실패를 숨기려고 검사를 지우지 않습니다.
- 서브에이전트는 꼭 필요할 때 한 번에 1~2개만 씁니다(사용량 한도 주의). 같은 파일을 동시에 고치게 하지 않습니다.
- 파일 줄바꿈 형식(CRLF/LF)은 원래대로 유지합니다. 한글·백슬래시가 섞인 치환은 셸 heredoc 대신 Edit 도구나 파일로 저장한 스크립트로 합니다(10-16에 정규식이 깨진 사고가 있었음).
- 개발 서버가 필요하면 `npx vite --host 127.0.0.1 --port 5173 --strictPort`를 백그라운드로 실행합니다. 포트가 이미 쓰이고 있으면 그 서버를 그대로 씁니다.
- 막히는 결정이 생기면 사용자를 기다리지 않고 "미리 승인한 결정"의 원칙(안전 → 고령 사용자에게 쉬운 쪽 → 비용 0 → 되돌리기 쉬운 쪽)으로 정합니다. 그리고 진척 문서의 "내린 결정" 칸에 남깁니다.

## 미리 승인한 결정

| 주제 | 결정 |
|---|---|
| 지원 화면 | **모바일 웹앱만** 개발합니다. PC에서는 항상 휴대폰 틀(지금의 "개발자 옵션 켠" 모양) 안에 모바일 화면을 보여 줍니다. |
| 개발자 모드 | **폐지합니다.** 오른쪽 아래 툴바(`DevToolbar`), 메뉴의 "화면 크기 바꾸기", `?dev`, localStorage `hongboitda-dev-view-v2`를 없앱니다. |
| PC 레이아웃 코드 | `pc-layout.css`는 import에서 빼고 `docs/archive/`로 옮깁니다(나중 PC 재설계 참고용). `useLayout() === "pc"` 분기는 지웁니다. |
| 내 홍보물 저장 | IndexedDB에 저장합니다(사진·포스터 Blob과 기록). 새 패키지 없이 브라우저 API를 씁니다. 저장 공간이 없으면 지금처럼 메모리로 동작하고 안내합니다. |
| 서버 저장·로그인 | 이번에는 하지 않습니다. 계정과 비용이 필요합니다. 로드맵에 둡니다. |
| 아이폰 사진 저장 | 모바일에서는 공유 시트(`navigator.share({files})`)로 "이미지 저장"을 고르게 하고, 안 되면 다운로드와 "사진을 길게 눌러 저장" 안내를 띄웁니다. |
| 카카오톡 보내기 SDK | 하지 않습니다. 카카오 개발자 앱 키와 도메인 등록이 필요합니다. 공유 시트 버튼 이름에 "카카오톡 등으로 보내기"만 씁니다. |
| API 호출 제한 | 서버 함수 안에 IP별 분당 제한(메모리)과 Origin 확인을 넣습니다. 외부 서비스(Upstash 등)는 쓰지 않고, Vercel Firewall 설정 방법을 문서에 적습니다. |
| 영상 시간 | `vercel.json`에 `api/video-start.js`의 `maxDuration: 60`을 넣고, 앱의 영상 시작 대기 시간을 서버 최대 시간보다 길게 맞춥니다. 다시 만들기 때 같은 idempotency key를 재사용합니다. |
| 채널 고르기 | 홍보 글 탭에 "어디에 올릴까요?"(인스타·네이버 플레이스·당근·카카오 채널) 칩을 다시 넣습니다. 누를 때만 그 채널로 AI를 1번 요청하고, 결과는 채널별로 기억합니다. 쉬운 화면에도 보입니다. |
| 포스터 색 | `colorthief`(MIT, 약 8kB) 설치를 승인합니다. 사진에서 강조색을 뽑고, 대비 4.5:1 보정을 거칩니다. "색 → 분위기대로"일 때만 적용합니다. |
| 포스터 프레이밍 | 사진 분석 응답에 피사체 위치(`[ymin,xmin,ymax,xmax]`, 0~1000)를 추가하고, 포스터에서 제품을 크게 잘라 넣습니다. 추가 호출은 없습니다. |
| AI 표시 | 저장·공유·복사할 때 "AI가 쓴 글이 들어 있어요"를 1회 안내합니다. AI 문구가 쓰인 포스터에는 모서리에 작은 "AI 활용" 표시를 넣습니다(사용자 사진만 쓴 기본 결과에는 넣지 않음). |
| 음성 입력 | 지원하지 않는 브라우저에서는 쉬운 화면의 "말로 하기"를 숨깁니다. |
| 첫 방문 | 홈에서 한 번만 "글씨 크게·쉬운 말로 볼까요? [쉬운 화면으로] [괜찮아요]"를 묻고, 답을 기억합니다. |
| 문구 모델 | `gemini-2.5-flash-lite`를 유지합니다. 404가 나면 `.env.example` 주석대로 `gemini-3.5-flash-lite`를 쓰라고 안내만 합니다(키 파일은 건드리지 않음). |
| 애매한 디자인 선택 | 고령 사용자 기준으로 더 큰 글씨, 더 적은 선택지, 한 화면에 한 가지 일을 고릅니다. |

## 작업 목록 (위에서부터)

### 1단계: 모바일 전용 전환 — ✅ 2026-10-17 완료 (커밋 메시지 "feat(ad_prototype): mobile web app only"). 2단계부터 시작합니다.
1. `src/DesktopStage.tsx`
   - 레이아웃을 항상 `mobile`로 고정합니다.
   - 768px 이상 화면에서는 휴대폰 틀(`html[data-view=mobile]` 모양)을 항상 보여 줍니다.
   - 아래 개발자 모드 요소를 모두 없앱니다: `DevToolbar`, `setOppositeView`, `oppositeViewOn`, 보기 상태 저장, 화면 너비 고르기.
   - 휴대폰 틀 위의 "휴대폰 화면 미리보기" 라벨은 없앱니다. 정식 화면으로 보이게 하기 위해서입니다.
2. `src/StudioScreens.tsx`: 메뉴의 "화면 크기 바꾸기" 토글과 PC 헤더 분기(`isPc`)를 지웁니다.
3. `src/main.tsx`: `pc-layout.css` import를 빼고 파일은 `docs/archive/pc-layout.css`로 옮깁니다. `reference-ui.css`의 `.dev-toolbar` 규칙과 `html[data-layout=pc]` 규칙을 정리합니다.
4. 검증 스크립트에서 PC 레이아웃을 전제한 검사를 "PC 화면 = 휴대폰 틀"로 바꿉니다. 대상은 `verify-reference-rebuild`, `verify-records-and-menu`, `verify-photo-step`, `verify-easy-mode`이고, 1024·1440 크기에서 틀 안의 모바일 화면을 검사하게 합니다. `docs/design/pc-redesign-plan.md`에 "2026-10-17 모바일 전용으로 결정"을 한 줄 추가합니다.

### 2단계: 공개 배포 전 필수 — ✅ 5~7번 2026-10-17 완료 ([진척사항_2026-10-17.md](진척사항_2026-10-17.md)). 15번부터 시작합니다(8~14번은 2026-10-17 완료).
5. API 호출 제한(IP별, 메모리)과 Origin 확인을 넣습니다. `api/_lib/http.js`의 공통 처리에 넣고, 테스트를 추가합니다.
6. `vercel.json`에 `maxDuration`을 넣고, 영상 시작 대기 시간과 idempotency key 재사용을 고칩니다(`src/video.ts`, `src/useAiVideo.ts`).
7. AI 표시를 마무리합니다(저장·공유·복사 안내, AI 문구 포스터의 "AI 활용" 표시).

### 3단계: 모바일 사용성
8. 내 홍보물을 IndexedDB에 저장합니다. 새로고침 경고는 저장에 성공하면 없앱니다.
9. 모바일 저장을 공유 시트로 바꾸고, 저장한 뒤 어디에서 찾는지 안내합니다.
10. 영상 탭에 들어갈 때 공유 파일을 미리 준비해서, 공유하기를 한 번만 누르면 되게 합니다.
11. 음성 입력 미지원 기기에서 버튼을 숨깁니다.
12. 첫 방문에 쉬운 화면을 제안합니다.
13. 아주 짧은 화면(높이 480px 이하)에서는 고정 막대들이 본문을 가리지 않게 합니다(쉬운 화면 툴바를 본문 안으로).

### 4단계: 결과 품질
14. 채널 고르기 칩을 넣습니다(위 결정대로).
15. 포스터 색 추출(colorthief)과 피사체 위치로 잘라 넣기를 합니다.
16. 문구 평가 묶음 `scripts/eval-promo.mjs`를 만듭니다. B_이창훈 `examples/products.json` 3개와 직접 만든 7개, 모두 10개로 구성합니다. 기계 점검(금지어, 반복, 길이, CTA)만 하고, 실제 Gemini 호출은 승인된 3번 안에서만 합니다.

### 마무리
17. 독립 점검을 합니다. 서브에이전트 1개가 모바일 3크기 × 기본·쉬운 화면을 캡처하고, 겹침·잘림·글자 크기(14px 미만)·대비(4.5:1)·키보드 이동을 측정합니다. 나온 문제를 고칩니다.
18. `docs/진척사항_2026-10-17.md`를 정리합니다. 한 일, 검증 결과, 내린 결정, 못 한 일과 이유를 적습니다. 그리고 `docs/품질개선_로드맵.md`와 `인수인계서.md`의 링크를 갱신합니다.
