같은 날 실기기 QA: ① 네이버 홍보 글만 끝까지 기본 글 — 지시문 "방문에 필요한 정보"가 "매일 ○시" 같은 운영 정보를 지어내게 해 금지어("매일")에 걸린 것으로 추정(실제 AI 응답은 미확인) → 네이버 지시문에 "방문 정보는 <shop>에 주어진 것만" ② 채널을 바꾼 뒤 AI가 쓰는 동안(최대 25초)에도 "기본 글로 만들었어요"가 떠 실패처럼 보임 → 쓰는 중에는 "글을 쓰고 있어요" ③ 홍보 글 [복사하기] 줄과 아래 메뉴 사이 14px 틈으로 글이 비침 → 줄을 틈까지 내림.
같은 날(사용자 "너무 느리다"): 첫 채널 AI 글이 오면 나머지 두 채널(네이버·당근)을 뒤에서 미리 받아 둔다 → 채널을 눌러도 기다림 없음. 첫 글이 실패하면 미리 받지 않는다. 홍보물 1건에 글 호출이 1회 → 3회(기관 Claude 우선, 유료로 넘어가면 건당 약 3원 × 3). 같은 주소 분당 20회 제한에 3배 빨리 닿으니 발표 날 제한 풀기와 함께 볼 것.
같은 날(사용자 "Vercel 첫 화면이 깨졌다 다시 뜬다"): 원인은 화면 비율 값(`--s`)을 첫 화면을 그린 **뒤에** 재서 1 → 약 1.1로 바뀌며 머리줄·본문·하단바가 한 번 튀던 것(레이아웃 흔들림 0.187). `StudioScreens.tsx` 측정을 `useLayoutEffect`로 옮겨 그리기 전에 잼 → 0. 로고 SVG 미리 받기, 영상용 명조 글꼴 CSS는 첫 화면을 막지 않게. 예시 이미지까지 미리 받으면 느린 망에서 JS가 1.2초 → 2.2초로 늦어져 뺐다.

**10-30 — 사진 확인·실패 복구(사용자 명시 승인).** 발표 준비 기간의 기능 고정 예외로, 사용자가 사진 의심 항목 경고와 인식 실패 복구 2가지를 추가하도록 승인했다.
- 사진은 종전처럼 정보 입력의 **[자동으로 채워 주기]를 눌렀을 때만** 분석한다. 사진 업로드만으로 새 AI 호출을 시작하지 않으며, 같은 요청에서 제품 정보와 확인 항목을 함께 받는다.
- 사람·동물·건물/배경, 술·담배·의약품·마약류 의심 물품·위험 물품·신용카드 등의 **의심 항목**과 이유를 안내한다. 정상 상품 사진의 손·평범한 배경을 불필요하게 분류하지 않도록 지시한다. 이것은 안전·법규·광고 가능 여부의 판정이나 탐지 보증이 아니다.
- 경고창에서 안내를 확인했다는 체크 후 계속하거나 다른 사진을 고를 수 있다. 닫기·ESC 후에도 미확인 안내와 생성 차단을 유지한다. 새 사진이나 새 분석 결과가 오면 확인을 다시 받는다. 카드 번호 등 개인정보는 가린 사진을 사용하도록 안내한다.
- 분석 실패·제품 정보가 없는 응답·API 미연결은 잠깐 사라지는 알림 대신 정보 입력 화면에 안내를 남긴다. **[다시 읽기]**는 같은 사진을 명시적으로 재시도하고, **[직접 입력하기]**는 작성 중인 값을 보존하며 이름 칸으로 이동한다. 자동 재시도는 하지 않는다.
- 다른 사진으로 바꾸면 사용자가 고치지 않은 이전 AI 추정값만 정리한다. 직접 입력·수정한 내용은 유지한다. 이전 사진의 늦은 응답이 새 사진에 적용되지 않게 요청 번호와 사진을 함께 확인한다.
- 공통 경고창의 Tab 순환에 체크박스를 포함하고, 첫 포커스는 제목에 두어 긴 안내를 건너뛰지 않도록 했다.
- 검증: 고정 잠금 파일 설치, TypeScript·프로덕션 빌드, API/클라이언트 파서의 비정상·중복·알 수 없는 분류 입력, 모의 응답 기반 모바일 경고·체크·생성 게이트·실패 지속·재시도·사진 교체를 점검한다. 실제 AI 정확도 시험과 유료 호출은 하지 않는다. 최종 통합 검증 결과는 상위 작업 기록에 별도로 남긴다.


**10-30 — 첫 영상 미리보기와 최종 통합 검증.** 사용자가 영상 버튼 첫 생성 시 검은 화면 대신 내용을 알아볼 수 있게 수정하도록 승인했다.
- 완성 파일의 해독과 3초 위치 탐색이 끝나기 전에는 상품 사진 표지를 표시하고, 실제 프레임이 준비되거나 재생이 시작되면 영상으로 전환한다. 파일별 준비 상태를 분리하고 해독 오류 때 사진과 오류 안내로 복구한다. 영상 렌더러·저장 파일·음악은 바꾸지 않았다.
- 최종 통과: TypeScript, 프로덕션 빌드, 새 사진 확인 회귀 8개, 영상 첫 프레임/재생/오류/소스 교체 회귀, API guard 8개, 홍보 글 규칙 35개. 실제 브라우저의 상품 사진 표지와 경고·실패 화면도 확인했다.
- 기존 회귀 부분 통과: AI API 14개와 첫 자동 채우기·결과 시나리오, 기존 사진 브라우저 6개·API 3개. 이후 구형 단계 선택자·포스터 준비 대기 시간 초과와 records의 서버리스 Chromium 컨텍스트 종료가 있어 전체 레거시 회귀 완료로 보고하지 않는다. 변경하지 않은 렌더러 품질 평가를 새로 완료한 것으로 쓰지 않는다.
- 실제 AI·유료 호출 0건. 탐지 정확도·전 품목 탐지·실기기 코덱/소리는 미검증이다. 직접 입력 경로까지 자동으로 전수 검사하지 않으며 [자동으로 채워 주기] 요청 때만 사진 확인 정보를 받는다.
- 사용자의 최종 자율 진행 승인에 따라 이번 세 가지 보완에 한해 main 통합을 진행한다. 일반 작업의 기능 고정·feature/UI-Screen 기본 정책을 전면 해제한 것은 아니다. 별도 발표 저장소에는 A21로 사진 확인·실패 복구를 설명했다.


**10-30 — 담배 사진이 경고 없이 보정된 제보 후 확인 순서 수정.**
- 원인: 기존 경고는 정보 입력의 자동 채우기에서만 요청돼, 사진 단계 배경 보정은 앞서 실행됐다. 원본 사진 [다음으로]에서 분석을 먼저 요청하고 확인/명시적 직접 확인 전에는 보정·생성을 막는다. 정보 입력에서 사진을 바꾸는 경로도 같은 확인을 거친다.
- 확인 응답은 입력 칸에 자동 적용하지 않는다. 자동 채우기를 누르면 같은 분석을 재사용한다. 사진 선택 자체는 요청하지 않고 [다음으로]/정보 입력의 사진 교체 때 요청한다. 기존 “자동 채우기만 분석” 결정은 이번 사용자 버그 수정 요청으로 변경했다.
- 실패·분류 누락·비정상 응답은 정상 판정과 구분한다. 다시 읽기·사진 교체를 제공하고, 기능을 계속 쓰려면 사용 제한 물품/민감정보 없는 상품 사진임을 직접 확인했다는 별도 체크가 필요하다. 창 닫기·ESC·직접 이름 입력만으로 확인을 건너뛸 수 없다.
- 담배 낱개뿐 아니라 포장·보루·전자담배·흡연 경고문/그림을 확인하도록 지시했다. 모델이 제품 이름을 담배/담뱃갑으로 명시했으나 분류를 빠뜨린 경우의 보완도 추가했다. 실제 이미지 인식 정확도 시험은 하지 않았으며 단어 검사가 픽셀 분류기라는 의미가 아니다.
- 모의 검증과 실제 모델 정확도를 구분한다. 실제/유료 호출 없이 사진 분석·배경 API를 모두 가로채 순서와 게이트를 검증한다. 최종 검증: TypeScript·프로덕션 빌드, 필수 사진 확인 회귀 12개, 기존 분류 파서 계약, API guard 8개 통과. 360×640 쉬운 화면에서 스크롤·체크·키보드 포커스·닫기 후 초기화도 실제 브라우저로 확인했다. 모의 응답 테스트라 실제 담배 사진 탐지 정확도 검증은 아니다.


**10-30 — 사진 경고 시범 구현은 보존하고 현 발표 버전에서는 보류(사용자 최종 결정).**
- 보정 전 원본 사진 확인 흐름을 구현·모의 검증했지만, 사용자가 추가 지연·복잡성과 실제 탐지 정확도 미검증을 이유로 현 발표 적용을 보류했다. 초기 시범 코드를 이미 사용자에게 제공한 역사와, 현재 기본 상태를 구분한다.
- 현재 일반 시연은 [다음으로]→배경 선택→정보 입력→결과 흐름으로 복귀한다. 사진 확인을 위한 추가 AI 호출·대기·확인 게이트를 두지 않고, 자동 채우기만 명시적으로 요청한다. 인식 실패 안내·같은 사진 재시도·직접 입력·영상 첫 사진 표지는 유지한다.
- 붉은 삼각형+명시적인 “게시 전에 직접 확인해 주세요” 경고창을 시범 코드로 추가했다. 사진·문구의 사용 권한과 내용을 직접 확인하도록 안내하고, AI 분석은 안전·광고 가능 여부의 보증이 아니라고 설명한다. 서비스의 법적 책임을 일괄 면제하는 문구는 쓰지 않는다.
- `VITE_PHOTO_REVIEW_EXPERIMENTAL=1`과 `MODE=mock` 모두 일치할 때만 활성이다. 기본 및 production에서는 비활성이다. 시연 사용자에게 토글을 보여 주지 않는다. 발표 부록 A21에서 시범 구현·적용 보류 이유로 설명한다.
- 실제/유료 AI 호출은 하지 않았고, 모의 응답에서 구현한 경고가 보인다는 것과 실제 담배 사진 탐지 정확도는 구분한다. 최종 검증: TypeScript·프로덕션 빌드, 현재 기본 모드 브라우저 6개, mock 전용 시범 모드 12개, 기존 분류 파서 계약, API guard 8개 모두 통과했다. 기본 모드는 다음/보정/수동 생성의 사진 분석 호출 0회와 요청형 자동 채우기·6.5초 이상 실패 안내·직접 입력/재시도를 확인했다. 시범 모드는 붉은 삼각형·안내 문구와 기존 확인 게이트를 검증했고 안내창만 별도 캡처했다. 실제/유료 AI 호출 0건.
