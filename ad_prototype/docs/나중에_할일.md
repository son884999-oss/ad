## [특급] 결과 화면의 "✦ 특급 영상으로 다시 만들기" (시연 코드 기기만)

- **상태:** 보류 — "나중에 검토"(사용자, 2026-10-19). 지금은 화면에 보이지 않게 둔다(`?premiumui`로만 예전 고급형 화면이 보임, `src/App.tsx` `premiumUi`).
- **진행 방식 (사용자, 2026-10-19):** 특급(재생성)은 **오늘 예산(1,000원) 밖**이고 **아직 팀과 논의하지 않았다.** 먼저 **결과물 예시를 만들어 팀과 공유**하고, 팀 의견을 받은 뒤에 화면에 넣을지 정한다. 예시를 만들 때는 별도 예산을 사용자에게 받고, [특급-품질]을 먼저 적용한 프롬프트로 만든다.
- **무엇:** 결과 화면 영상 탭에 버튼 하나. 누르면 Higgsfield 움직임 영상(세계가 바뀌는 콘셉트, `api/_lib/video-prompt.js` `conceptPrompt`) + 브라우저 후편집(`src/videoCaptioner.ts`, 고급형 스타일). 포스터·홍보 글은 그대로.
- **왜 결과 화면인가:** 입력 화면의 "고급" 분위기 버튼과 겹치지 않고, 기본 결과를 먼저 본 뒤 원할 때만 1~3분을 더 기다린다. 시연에서 "기본 → 특급" 차이를 눈앞에서 보여 줄 수 있다.
- **누가 보나:** 시연 코드 기기만. Vercel 환경 변수 `PREMIUM_ACCESS_CODE`, 시연 휴대폰에서 `https://주소/?demo=코드`로 한 번 열면 그 기기에 기억(`src/premiumAccess.ts` `hasPremiumCode`), 서버도 `x-premium-code`를 확인(`api/_lib/paid.js`). 이미 만들어져 있음.
- **어디:** `src/App.tsx` 영상 탭(지금 `startPremium`·`aiVideo.start`·`premiumSteps`가 있는 곳), `src/AiVideoPanel.tsx` 진행 단계. 기존 "고급형 특별 연출" 스위치(`SpecialFilmToggle`, `details.specialFilm`)와 사진 화면의 기본형/고급형 선택(`VideoModeToggle`)은 C안 구현 때 없애거나 숨긴다.
- **먼저 고칠 것:** 콘셉트 영상 실제 1번(2026-10-18)에서 ① 테이블에 가짜 글자 ② 밀가루가 케이크를 덮음 ③ 제품이 화면의 약 20%로 작음. → [특급-품질] 항목.
- **같이 할 것:** 고급형 후편집 소리(`src/videoCaptioner.ts` `addSound`)는 아직 예전 합성음(잡음 "휙"·차임·패드). 기본형처럼 `src/videoSound.ts`(클래식 + 효과음, 리미터)로 바꾼다.
- **끝난 기준:** 시연 코드 기기에서만 버튼이 보이고, 누르면 진행 단계 → 완성 영상으로 바뀜. 코드 없는 기기에는 버튼이 없고 서버도 거절(`verify:guard`). 같은 사진으로 두 번 눌러도 결제 1번(결제 키). `verify:video`에 검사 추가.
- **비용:** 1번 약 300~450원(Kling 2.5 Turbo 5초). 시험 호출은 사용자 승인 횟수 안에서, 쓰기 전에 [디자인개선_루프.md](디자인개선_루프.md) "호출 사용량"에 먼저 기록.

- **비용:** 1번 약 300~450원.

## [회원가입] Supabase Auth + 내 홍보물 서버 저장

- **상태 (2026-10-19): 코드 완료, 설정 대기.** 카카오·Google·이메일+비밀번호, 바로 시작하기 유지, 서버 저장(사진·배경·포스터·영상·글), 개인정보 처리방침 초안(`src/PrivacyPolicy.tsx`, 책임자·위탁은 팀이 확인), 회원 탈퇴(`api/account-delete.js`). 사용자가 할 일: [회원가입_설정안내.md](회원가입_설정안내.md)(Supabase 프로젝트·SQL·카카오·Google·Vercel). 네이버는 준비 중으로 둠. 점검 `npm run verify:auth`.
- **무엇:** 로그인 화면(이미 카카오·네이버·Google·아이디 버튼 있음, 지금은 "준비 중")을 실제로 연결. Supabase Auth(카카오 기본 지원, 네이버는 별도 OIDC 필요할 수 있음). 내 홍보물(지금 기기 IndexedDB, `src/recordsStore.ts`)을 Supabase DB로.
- **결정이 필요한 것:** 로그인 방식(카카오만 / 카카오+Google / 아이디 포함), 비로그인 사용 허용 여부("바로 시작하기" 유지), 저장 기간·용량(사진은 줄여서 저장).
- **주의:** Vite + Vercel 함수 구조라 Next.js 전용 모듈(NextAuth 등)은 안 맞는다. GitHub에서 모듈을 가져오면 라이선스(MIT·Apache 가능, AGPL 피함)와 최근 6개월 관리 여부 확인. **개인정보 처리방침**(무엇을 왜 모으는지) 화면 필요. 키는 서버 환경 변수로만.
- **로드맵 연관:** 로그인이 실제로 생기면 "로그인"을 다시 주 버튼으로(`reference-ui.css` 끝의 로그인 규칙 두 줄 삭제) — [품질개선_로드맵.md](품질개선_로드맵.md) "코드 구조 정리".
- **끝난 기준:** 휴대폰에서 가입·로그인·로그아웃, 다른 기기에서 같은 계정으로 내 홍보물이 보임, 비로그인으로도 만들기 가능(정한 경우), 검증 스크립트 추가.

## [제품합성] 제품만 오려 내고 배경만 AI로 만들어 합치기

- **상태:** 조건 충족, 결정 대기 (2026-10-19). 보강한 프롬프트(`api/_lib/background.js`)로 마카롱을 다시 해 보니 흰 꼬끄 색·녹차/초콜릿 필링·배치는 지켰지만 **뒤집힌 꼬끄 1장이 여전히 완성 마카롱으로 바뀜**. 지금은 결과 화면의 "바뀐 사진 / 원래 사진" 고르기로 막아 둠. 배경 제거 모델을 들이는 큰 작업이고 합성 품질(조명이 안 맞아 붙인 티)도 장담할 수 없어, 사용자 결정 후 진행. 비교 그림: `outputs/시연_최고결과물_2026-10-18/배경바꾸기_비교/`.
- **무엇:** 원본에서 제품 영역을 오려 내고(배경 제거), Gemini에는 빈 배경만 그리게 한 뒤 브라우저에서 합성. 제품 픽셀이 절대 바뀌지 않는다.
- **주의:** `@imgly/background-removal`은 AGPL·모델 40~80MB라 피한다. 후보: Gemini 분할 마스크, 서버 쪽 가벼운 모델.
- **끝난 기준:** 마카롱·케이크·라테 사진에서 제품 픽셀이 원본과 같고 경계가 자연스러움.

## [인공지능표시] AI 생성물 표시 마무리 (정식 서비스 전)

- **기관 답 (2026-10-19):** "통합해서 표현이 되면 통합해서 표현하고, 아니면 보수적으로 접근하여 AI 활용했다는 표시를 넣어 달라." → **적용함:** 문구든 배경이든 AI가 들어가면 **"AI 활용" 표시 하나**(따로 나누지 않음)를 포스터와 기본형 영상 모두에(영상은 오른쪽 위, 스토리 상단 띠 아래). AI가 전혀 없으면 표시 없음. 남은 것: 다운로드·공유 때 1회 안내, 고급형 AI 영상 파일, C2PA.
- **이전 상태:** 기관에 문의 중(문안은 사용자에게 전달). 답이 오기 전까지 지금처럼 "AI가 관여했을 때만" 표시: 문구가 AI면 앱 안내 + PNG 정보 + 포스터 "AI 활용", 배경이 AI면 포스터 "AI 활용". 제안안: 문구만 AI면 포스터의 보이는 표시는 빼고, 배경을 AI로 바꿨을 때만 보이게(영상에도). 기관 답에 맞춰 정한다.
- **무엇:** 인공지능기본법 제31조. 다운로드·공유 때 1회 안내, AI 영상 파일에도 보이는 표시, 여유 시 C2PA. 배경 바꾸기 사진에도 "AI 활용" 표시. [품질개선_로드맵.md](품질개선_로드맵.md) 5절.

## [결제] 실제 결제 모듈을 단다면 (검토 메모, 2026-10-19)

- **상태:** 아직 결정 안 함. 시연·QA 단계에서는 **결제사의 테스트 모드만** 권장(실제 돈이 오가지 않음).
- **실결제 전에 필요한 것 (사업 쪽):** 사업자등록, 통신판매업 신고, 결제사(토스페이먼츠·포트원 등) 가맹 심사 — 심사는 실제 서비스 주소, **이용약관·환불 규정·사업자 정보(상호·대표·주소·연락처) 화면 하단 표기**를 본다. 팀 프로젝트·개인 명의로는 실결제 계약이 어렵다.
- **법·소비자 보호:** 전자상거래법 청약철회(디지털 콘텐츠는 "만들기 시작하면 철회 제한"을 결제 전에 분명히 알리고 동의 받기), 영수증·부가세, 미성년자 결제, 정기결제(구독)라면 해지·자동연장 고지.
- **코드 쪽 위험:**
  - 결제 결과는 **서버에서 결제사에 다시 확인**(금액·주문번호 검증, 웹훅)해야 함. 브라우저가 "결제됨"이라고 보내는 값만 믿으면 위조 가능.
  - 결제가 되면 **횟수·이용권을 회원 DB에** 기록해야 함. 지금의 하루 횟수 제한은 서버 인스턴스마다 따로 세는 느슨한 방식이라 결제와 묶기엔 부족 → Supabase 표(또는 Upstash)로 옮겨야.
  - AI 생성이 **실패하면 자동 환불·이용권 복구**가 필요(지금은 실패하면 원래 사진·기본 문구로 대체만 함).
  - 원가 계산: Gemini 배경 장당 약 26~90원, Higgsfield 영상 약 300~450원, 기관 키 한도 — 가격이 원가와 실패율을 넘어야 함.
  - 회원가입이 전제(누가 샀는지). [회원가입]은 완료.
- **권장 순서:** 테스트 모드로 "이용권 구매 → 서버 확인 → 회원 DB에 이용권 → 쓸 때 차감 → 실패 시 복구"를 먼저 만들고, 실결제는 사업자·심사가 준비된 뒤.

## [기술문서] 기술 설계서 2~3장 (시스템 구성도 + 기술 스택 + 오픈소스 고지)

- **상태:** 나중에 (사용자, 2026-10-19). 발표·보고서·팀 공유용.
- **꼭 강조할 메시지 (사용자, 2026-10-19):** 포스터·기본형 영상의 **디자인·연출·편집·소리는 AI API 없이 브라우저 안의 자체 코드와 오픈소스**로 만든다(포스터 렌더러, 모션 영상, 녹화, MP4 정리, 소리 믹스). 외부 AI는 **홍보 문구 작성**과 **(사장님이 고를 때만) 배경 바꾸기** 두 곳뿐. 그래서 즉시·무료·서버 비용 없음, 배경 바꾸기를 안 고르면 사진이 외부 AI로 가지 않음. 결과물의 "AI 활용" 표시는 기관 권고대로 보수적으로(AI가 쓴 문구나 AI 배경이 들어가면) 붙이고 있다는 점도 함께 설명 — 표시는 "내용" 기준이고, "디자인을 AI가 했다"는 뜻이 아님.
- **사용자 요청 형태:** 구성도와 기술 스택 표를 따로 만들기보다, **"어떤 입력을 받아 → 어떤 기술·구조로 처리해 → 어떤 산출물을 내는지"를 한눈에 보는 통합 구조도**. 한 장에 담고, 넘치면 최대 3장.
- **무엇:** 서비스 흐름도(`서비스흐름도/`)와 같은 방식(HTML → PNG/PDF)으로 2~3장.
  1. **시스템 구성도(아키텍처):** 휴대폰 브라우저(Vite + React 화면, 포스터 렌더러, 모션 영상·녹화·MP4 정리·소리) ↔ Vercel 함수(`api/`: 사진 분석, 홍보 글, 배경 바꾸기, 영상) ↔ 외부 AI(기관 Claude COPA, Gemini 글·그림, Higgsfield 영상). 데이터가 어디서 어디로 가는지, 키는 서버에만 있다는 것.
  2. **기술 스택과 규칙:** 언어·프레임워크·라이브러리와 쓰는 이유, AI 순서(Claude → Gemini 무료 → 유료), 유료 호출 보호(분당 횟수·하루 상한·결제 키·시연 코드), 품질 점검(`verify:*`·`audit:screens`·`eval:*`), AI 표시 규칙.
  3. **오픈소스·음원 고지:** npm 패키지와 라이선스(`package.json`·`pnpm-lock.yaml`에서 뽑기), 음원(`docs/라이선스/음원.md`), 팀원 폴더(A_~F_)에서 이식한 부분과 출처(README "팀원별 이식" 표).
- **끝난 기준:** 처음 보는 사람이 2~3장만 읽고 구조·기술·출처를 설명할 수 있음. 실제 코드와 다른 내용이 없음(파일 경로로 확인).
