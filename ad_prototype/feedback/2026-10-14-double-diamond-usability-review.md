# 더블다이아몬드 통합 사용성 검토

- 일시: 2026-10-14, Asia/Seoul
- 작업 브랜치: `feature/UI-Screen`
- 비교 기준 커밋: `0c9e11ef5575342150f312a0b4610677d772a4b9`
- 범위: 홈 → 사진 → 설명 → 결과 → 수정 → 내 홍보물, 전체 메뉴와 개별 결과 제작
- 방법: 사용자에게 받은 실제 피드백, 코드 조사, Chromium의 실제 화면 검토, 과업별 자동 통합 테스트, 인지적 과업 점검
- 실사용자 참가자 테스트: 미실시. 아래의 예상 반응은 평가자의 가설이며 사용자 발언·만족도·성공률을 측정한 결과가 아니다.
- 추가 요청: 일관성·직관성·시인성과 UI/UX 디자이너 관점을 나누어 5회 이상 반복. 총 6개의 과업별 더블다이아몬드 사이클로 검토·개선·재검증했다. 6회는 참가자 실험 횟수가 아니다.

## 접근 방법

[Design Council의 Double Diamond](https://www.designcouncil.org.uk/resources/the-double-diamond/)에 따라 발견 → 정의 → 개발 → 전달로 진행했다. 더블다이아몬드는 설계 과정이며, 통합 테스트는 전달 단계의 검증 도구로 사용했다. 실제 사용자와 함께 확인하는 발견·공동 설계는 기존 대화의 피드백으로 일부만 수행했고 별도 참가자 검증은 남아 있다.

| 단계 | 수행 내용 | 남긴 근거 |
| --- | --- | --- |
| Discover · 발견 | 사용자의 확대·재생 버튼 발견성, 불필요한 메타 정보, 결과 배치 불일치 피드백을 정리. 처음 만들기·정보만 입력하기·돌아오기·키보드 사용·결과 가져오기 과업을 전체 흐름에서 실행 | 수정 전 화면, `discovery.json`, 실제 재생/정지 시 사진 배율 |
| Define · 정의 | 한 동작에는 한 이름과 조작 방법을 쓰고, 메뉴 이동은 입력을 지우지 않으며, 버튼 상태는 실제 화면 동작과 일치해야 한다는 문제로 수렴 | 아래 우선순위와 해결 기준 |
| Develop · 개발 | 각 문제의 대안을 비교해 기존 구조를 보존하는 수정 선택. 공통 버튼·기존 상태 재사용·메뉴 위치 계산·사진 움직임 정지 개선 적용 | 변경된 컴포넌트와 CSS |
| Deliver · 전달 | 전체 과업과 결과 회귀 검사, 7개 폭·두 모드·짧은 화면·가로 화면의 실제 렌더링 확인. 실제 참가자용 검증 과업 준비 | 테스트 스크립트, 현재 화면 캡처, 후속 관찰 시트 |

## 발견한 문제와 개선

P1은 과업 실패·입력 손실, P2는 탐색·이해 비용으로 분류했다. 정량적인 사용성 점수는 부여하지 않았다.

| ID / 우선순위 | 재현한 문제 | 사용자가 느낄 가능성이 있는 영향 · 가설 | 적용한 개선 |
| --- | --- | --- | --- |
| D1 / P1 | 입력 중 하단 ‘만들기’를 다시 누르면 사진과 상품명이 초기화됨. 홈의 만들기·종류 선택에도 같은 초기화 함수 사용 | 단순 이동을 초기화로 예상하기 어려워 작성 의지가 떨어질 수 있음 | 하단 만들기는 현재 단계로 복귀. 홈은 입력이 있으면 ‘홍보물 이어 만들기’. 종류 선택은 기존 사진·정보를 보존하고 확인 안내. 명시적인 ‘새 홍보물 만들기’는 초기화 유지 |
| D2 / P1 | 메뉴의 스크롤 컨테이너에 `transform`이 적용되어 안쪽 고정 메뉴도 함께 이동. 390×844에서 메뉴 상단 위치가 763px에서 287px까지 이동 | 설정 글이 메뉴에 가려지고 이동 버튼이 사라지거나 중간으로 이동해 길을 잃을 수 있음 | 메뉴를 transform 없이 가운데 배치하여 하단 메뉴를 화면 아래에 고정. 설정·키보드 포커스가 고정 메뉴 아래에 가려지지 않게 스크롤 조정. 선택된 메뉴 버튼을 다시 누르면 닫힘 |
| D3 / P2 | 사진 단계는 ‘사진 바꾸기’, 설명 단계는 ‘사진 변경’. 파일 선택용 label에는 일반 버튼의 키보드 조작이 없음 | 같은 기능을 다른 기능으로 받아들이거나 키보드로 찾기 어려울 수 있음 | 두 단계 모두 같은 ‘사진 바꾸기’ 이름·버튼 스타일. 실제 button으로 Enter·Space 지원. 보이지 않는 파일 입력은 별도 탭 정지·중복 접근성 컨트롤로 노출하지 않음 |
| D4 / P2 | 빈 상품명이 처음부터 `aria-invalid=true`. ‘소개·알리고 싶은 점’의 접근성 이름이 ‘제품 설명·강조할 특징’으로 다름 | 입력 전부터 오류로 인식하거나 음성 조작·화면 읽기에서 보이는 이름과 다른 항목으로 이해할 수 있음 | 상품명 필수 유지, 초기 오류 선언 제거. 보이는 항목명과 접근성 이름 일치. 두 선택 항목은 실제 선택 상태 유지. ‘상품명만 입력해도 결과를 볼 수 있어요’ 안내와 제목으로 필요한 입력을 명확히 함 |
| D5 / P2 | 홈·메뉴·결과에서 포스터/이미지, 동영상/영상, 홍보 글/문구가 혼용 | 메뉴 선택과 결과가 같은 종류인지 다시 판단해야 할 수 있음 | 핵심 결과 종류의 표시 이름을 이미지·영상·문구로 통일. 저장하기·복사하기는 실제 가져오기 방식에 맞는 동사를 유지 |
| D6 / P1 | ‘일시 정지’ 후 사진이 계속 움직이며 원래 크기로 축소됨. 정지 후 배율이 약 1.03286 → 1.00898로 변함 | 정지 버튼이 거꾸로 재생한다고 느끼거나 재생 상태를 믿기 어려울 수 있음 | 화면의 사진 움직임을 CSS animation의 재생/정지 상태로 제어. 정지하면 현재 위치 유지, 다시 재생하면 이어 움직임. 탭 이동 시 정지, 동작 줄이기 설정 존중 |
| D7 / P2 | 사진 준비 완료가 사진 확인 영역과 별도 상태 문장에 중복 표시됨 | 같은 완료 정보를 반복 읽어 주 행동을 찾는 데 방해가 될 수 있음 | 시각적 완료 안내는 한 번만 표시하고 별도 상태 영역은 화면 읽기용으로 유지. 교체 실패는 경고 역할로 안내 |
| D8 / P2 | 문구 결과가 입력 화면과 같은 textarea로 표시됨. 확대 뒤 키보드 포커스는 확대 버튼에 남아 새로 생긴 이미지 스크롤 영역을 건너뜀 | 결과를 직접 편집할 수 있다고 기대하거나 확대 내용을 키보드로 읽기 어려울 수 있음 | 문구를 선택·스크롤 가능한 결과 문서 영역으로 표시. 확대 시 이미지 스크롤 영역에 포커스. 원문 복사와 읽어주기 유지 |
| D9 / P2 | 결과 상태 문장과 해당 행동 버튼의 접근성 연결이 없음. 대체 복사 방식의 임시 입력을 제거하면 키보드 포커스가 body로 떨어질 수 있음 | 완료를 확인하기 어렵거나 복사 후 키보드 위치를 잃을 수 있음 | 세 종류에 공통 상태 설명 연결. 대체 복사 후 포커스가 body에 있을 때만 같은 버튼으로 복원 |

| 평가 축 | 판별 기준 | 관찰한 문제 | 수정 후 근거 | 아직 확인하지 못한 것 |

## 6회 더블다이아몬드 사이클

각 회차에서 발견을 넓힌 뒤 문제를 좁혔고, 대안을 비교해 수정 범위를 정한 후 해당 과업을 다시 실행했다. 앞서 적용한 관련 수정도 해당 회차에서 다시 확인했다. 같은 참가자 실험을 6회 실시하거나 만족도를 6번 측정한 것은 아니다.

| 회차 | Discover · 발견 | Define · 정의 | Develop · 대안과 개선 | Deliver · 재검증 |
| --- | --- | --- | --- | --- |
| 1 · 필수 입력·용어 | 필수 입력에 대한 사용자 정정, 초기 오류 상태, 상품명/가게명 예시 혼동, 표시 이름 불일치 | 반드시 필요한 입력과 같은 개념의 이름을 일치시킨다 | 항목마다 상태 설명을 붙이는 방식과 공통 안내 비교 → 상품명 필수·선택 항목 표시 제거 유지, 제목/안내/접근성 이름/상품 예시를 정리 | 상품명만으로 진행·공백 차단·두 항목 선택 상태, 3개 화면 통과 |
| 2 · 사진 선택·교체 | 단계별 다른 명칭·label 조작, 중복 완료 문장, 교체 실패의 오류 의미 | 같은 사진 작업을 같은 이름·방법으로 제공하고 실패 시 원본 보존 | label에 키보드 로직 추가와 native 버튼 비교 → 공통 버튼, 두 업로드 트리거, 시각적 완료 중복 제거·오류 경고 | 카메라/텍스트 같은 파일 선택창, Enter 교체, 동일 버튼 스타일, 손상 사진에도 입력 보존, 3개 화면 통과 |
| 3 · 메뉴·작업 복귀 | 스크롤 중 고정 메뉴 이동, 만들기 재선택의 초기화 | 메뉴 이동은 현재 작업으로 돌아가는 행동이어야 한다 | 확인창 추가와 입력 보존 비교, 메뉴 재배치와 transform 제거 비교 → 기존 구조에서 고정·이어 하기·명시적 새 시작 | 스크롤 전후 메뉴 위치 유지, 설정 가림 없음, 홈·만들기 복귀 시 입력 보존, 3개 화면 통과 |
| 4 · 결과 배치·피드백 | 기존 배치 불일치 피드백, 상태 연결 부재, 대체 복사 후 포커스 손실 | 결과가 달라도 가져오기 위치와 완료 확인 방법이 안정적이어야 한다 | 탭별 개별 버튼과 공통 행동 영역 비교 → 공통 프레임·버튼 유지, 상태 연결·대체 복사 후 포커스 복원 | 세 프레임·행동 스타일 일치, 주요 버튼 텍스트 대비 기준, 완료 연결·대체 복사 포커스, 3개 화면 통과 |
| 5 · 재생·정지 | 실제 정지 후 사진 배율이 줄어드는 현상 | 정지의 이름·상태와 움직임을 일치시킨다 | 실제 영상 플레이어 교체와 화면 움직임 수정 비교 → 생성 함수 유지, 현재 움직임의 정지·재개와 동작 줄이기 | 3개 화면에서 정지 후 배율 변화 0, 재개 동작·탭 이동 정지·동작 줄이기 통과 |
| 6 · 확대·문구 읽기 | 확대 뒤 스크롤 영역을 건너뛰는 포커스, 문구 결과의 입력창 표현 | 결과를 읽는 작업과 입력하는 작업을 구분하고 키보드로 전체 내용에 접근한다 | 읽기 전용 textarea 유지와 결과 문서 영역 비교 → 결과 문서·확대 영역 포커스·방향키 읽기 | 이미지 이동·긴 문구 스크롤·표시 원문/클립보드 일치·읽어주기 원문 비교, 3개 화면 통과. 음성 엔진은 모의 구현 |

## 일관성 기준

- **이름:** 홈·메뉴·결과·기록에서 이미지·영상·문구. 사진 변경은 어디서나 사진 바꾸기.
- **위치:** 이미지·영상은 같은 프레임 크기와 오른쪽 아래 확대·재생 위치. 세 탭의 저장·복사는 같은 주 행동 영역.
- **스타일:** 사진 바꾸기 버튼의 글자·여백·모서리와 결과의 주 행동 스타일 공통. 선택 상태는 색상과 접근성 상태를 함께 사용.
- **동작:** 이동·이어 하기는 입력 보존. 새 만들기는 명시적인 초기화. 재생/정지 표시와 실제 사진 움직임 일치.
- **피드백:** 기존 완료/오류 메시지와 복사 실패 후 재시도 유지. 소개·알리고 싶은 점에는 필수/선택 표시를 다시 붙이지 않음.
- **자료 보존:** 원본 사진·포스터 출력 크기·복사할 원문·다운로드 방식 유지. 비활성화한 하위 기능은 복원 가능한 코드로 유지.

## 검증 결과

- `pnpm build`, `pnpm exec tsc --noEmit`, `git diff --check`: 통과.
- `pnpm verify:cycles`: 6회차 × 3개 화면(390×844, 320×568, 1440×844)의 과업 점검 통과. 각 회차의 `cycle-N.json`에 실제 근거를 기록.
- `pnpm verify:usability`: 7개 폭(320·375·390·430·768·1024·1440px) × 일반/간편 모드 14개와 짧은·가로 화면 6개, 총 20개 조합 통과. 사진 선택·교체, 필수/선택, 포커스 가림, 입력 유지·이어 하기, 개별 종류 제작, 기록 재열기, 명시적 새 시작을 연결해 확인.
- `pnpm verify:results`: 14개 화면 조합 통과. 공통 프레임·주 행동의 좌표·크기 차이 1px 미만, 확대·재생·키보드 탭 이동, 클립보드 원문 일치, 복사 실패/재시도, PNG·영상 파일 다운로드, 영상 준비 취소 후 재시도 확인.
- 실제 모바일·PC 캡처를 확인했다. 마지막 문구 문서 화면에서 과거 CSS가 남긴 크기 조절 표시를 제거하고 해당 회차와 모바일 흐름을 다시 확인했다.
- `copyFinalText`, `createPosterFile`, `createVideoFile`은 기준 커밋과 함수 본문이 동일함을 비교했다. 생성 API·원본 파일 해상도·출력 파일 생성 함수는 변경하지 않았다.
- 모든 판정은 브라우저 과업 검사와 평가자 화면 검토이다. 참가자 성공률이나 사용자 만족도를 뜻하지 않는다.

## 실제 참가자에게 확인할 과업 · 미실시

대상은 첫 사용자와 모바일·큰 글씨를 선호하는 사용자로 나누고 평소 사용하는 휴대폰에서도 관찰한다. 버튼 이름이나 위치를 먼저 알려주지 않고 화면을 읽으며 생각을 말하도록 요청한다. 개인정보가 없는 샘플 사진을 사용한다.

| 과업 | 관찰할 행동 | 성공 기준 | 확인 질문 |
| --- | --- | --- | --- |
| 제공한 사진으로 ‘데일리 샴푸’ 홍보물을 만든다. 추가 소개는 모른다고 가정 | 사진 선택 발견, 상품명만으로 진행, 선택 입력 때문에 멈추는지 | 도움 없이 결과에 도달 | 어느 항목을 꼭 적어야 한다고 생각했나요? |
| 사진을 다른 사진으로 바꾼다 | 사진 단계·설명 단계의 같은 행동을 인식하는지 | 두 단계에서 변경 가능, 입력 유지 | 두 버튼이 같은 기능으로 느껴졌나요? |
| 메뉴에서 글씨 설정을 바꾼 뒤 원래 작업으로 돌아온다 | 메뉴 스크롤, 하단 버튼 발견, 닫기 발견 | 설정 변경·작업 복귀, 입력 유지 | 어디로 돌아가는지 예상할 수 있었나요? |
| 이미지 내용과 사진 움직임을 확인한다 | 확대·재생 버튼 발견, 정지 결과 이해 | 두 컨트롤을 찾아 조작 | 누른 뒤 예상과 다르게 움직인 곳이 있나요? |
| 이미지를 기기에 보관하고 문구를 다른 앱에 붙여넣을 수 있게 가져온다 | 탭 전환 후 저장/복사 위치 찾기, 두 행동의 의미 구분 | 파일 다운로드 및 클립보드 가져오기 | 저장과 복사의 차이가 이해됐나요? |
| 입력 내용을 고치고 홈을 거쳐 작업을 이어 간다 | 수정 경로, 새 만들기와 이어 하기 구분 | 수정 내용 보존 | 내용을 잃을 것 같아 망설인 순간이 있었나요? |
| 내 홍보물에서 해당 문구를 다시 연다 | 필터·종류·다시 보기 이해 | 원하는 결과 종류를 다시 열기 | 어느 결과가 열릴지 예상한 대로였나요? |

참가자별 기록: 완료/실패, 진행 시간, 잘못 누른 곳, 멈춘 화면, 도움 제공 여부, 실제 발언, 체감 난이도. 현재 값은 모두 미측정이다. 참가자의 결과를 자동 통합 테스트 통과 수와 합치지 않는다.

## 남아 있는 한계

- 참가자 관찰이 없어 발견성·불안감·만족도 개선은 아직 가설이다. 현재 대화에서 받은 실제 사용자 피드백과 브라우저에서 재현한 결함은 구분해 사용했다.
- Android Chrome·iOS Safari 실기기의 파일 선택, 가상 키보드, 음성·진동, 저장 위치는 별도 현장 확인이 필요하다. 짧은 Chromium viewport는 가상 키보드나 OS 다운로드 UI 자체를 재현하지 않는다.
- 영상 화면은 기존 사진 움직임 예시이고 저장 파일의 실제 플레이어가 아니다. 실제 AI API의 응답·품질·지연과 저장 영상의 모든 프레임은 검증 범위 밖이다.
- 내 홍보물 기록은 현재 창의 메모리에서 유지된다. 새로고침 후 지속 보관 기능은 추가하지 않았으며 기존 제한 안내를 유지했다.
