# 다음 작업 인계

현재 목표는 모바일·시니어 중심의 전면 UI 재설계와 반복 개선이다. 단순한 색 변경으로 목표를 축소하지 않는다. 기존 기능은 보존하고, 2000~2020 보존 홈페이지를 디자인 주근거로 삼는다. 검증된 역사 레퍼런스와 수정 이유는 `UI_DESIGN_REVIEW.md`에 있다.

## 현재 검증된 상태

- 로그인: 로고 아래 한 개의 로그인 창. 회원가입 전환·비밀번호 보기·체험 시작·읽어주기 유지.
- 로그인 이후: 사진→설명→저장 3단계 안내, 하단 만들러 가기.
- 기본 간편모드, 컴퓨터 왼쪽/모바일 하단 퀵바, 이미지/영상/홍보 글·구독/건당 메뉴.
- 결과 3개: 좁은 화면1열/넓은 화면3열. 2+1 배열 제거.
- 긴 미디어 문구에서도 재생·저장·복사 조작 가능. 원문 확인·다음 결과 링크·단계 제목 초점.
- 선택 검색어 접기, 현재 검색어 미리보기, 기본값만 상품 설명에 맞게 갱신, 사용자 수정값 보존.
- 새 작업 직후1회 되돌리기. 새 입력/다른 기록/로그아웃 시 만료.
- `verify:zoom`: 전용 Chromium 프로필의 실제100/200% 확대를 측정해 입력·키워드·재생·복사·PNG·되돌리기 검사. 사용자 브라우저 프로필을 사용하지 않음.
- `verify:recovery`: 사진 교체 실패 때 기존 사진 보존·읽기 중 다음 잠금·최신 파일 선택만 반영. 읽어주기 준비 취소/대기8초 제한/중단/미지원은 모의 상태 검수이며 실제 음질은 미검증.

## 재개 시 확인

1. `git status`, 현재 브랜치/커밋을 먼저 확인하고 사용자 변경을 보존한다.
2. `AGENTS.md`, 최신 `UI_DESIGN_REVIEW.md`를 읽는다. 이 인계 파일만으로 실행 중이라고 판단하지 않는다.
3. HTTP 서버 상태를 확인하거나 `start-preview.cmd`로 기존 서버에 연결/시작한다.
4. 필요한 범위만 `pnpm build`, `pnpm exec tsc --noEmit`, `pnpm verify:ui`, `pnpm verify:readability`, `pnpm verify:studio`, `pnpm verify:zoom`으로 검증한다. 새 실패나 변경이 없으면 같은 검사만 무한 반복하지 않는다.
5. 사용자 관점·개발 관점·디자인 레퍼런스 관점의 세 역할로 검토한다. 수정 후 외부 레퍼런스를 다시 검색하고 실제 발견된 문제를 다음 수정에 반영한다.

## 남은 검수 우선순위

- 실제 Android/iOS 터치·가상 키보드·스크린리더. 데스크톱 에뮬레이션을 실제 기기 검수라고 표시하지 않는다.
- 실제 시니어 사용자가 메뉴와 생성 단계를 이해하는지. 에이전트의 사용자 관점 검토는 실제 피드백을 대체하지 않는다.
- 반복 선택/입력/되돌리기와 기록 복원의 경계 상황, 사진 크기/형식 오류의 회복성.
- 사용자가 허용한 Figma 등 외부 도구는 디자인 검토에 실질적으로 필요할 때 활용한다. 단순히 허용됐다는 이유만으로 도구를 설치하거나 새 파일을 만들지 않는다.

## 사용량 한도 뒤 재개

현재 목표에 한도 해제 후 계속 진행하라는 사용자 의도가 포함되어 있다. 목표는 활성 상태로 유지한다. 다만 현재 세션에는 한도 해제 감지나 일반 자동 재개 예약 도구가 제공되지 않아 예약 설정 완료로 표시하지 않는다. 한도 상태/재개는 앱 또는 사용자가 제어한다. 공식 목표 안내: https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex

새 유료 영상 요청, API 키 읽기/출력, main 자동 병합, 배포는 UI 개선에 필요한 기본 작업으로 추정하지 않는다. 로그인 인증·결제·AI 서버 연결은 여전히 프로토타입 외부 통합 과제다.
