## [특급] 결과 화면의 "✦ 특급 영상으로 다시 만들기" (시연 코드 기기만)

- **상태:** 보류 — "나중에 검토"(사용자, 2026-10-19). 지금은 화면에 보이지 않게 둔다.
- **무엇:** 결과 화면 영상 탭에 버튼 하나. 누르면 Higgsfield 움직임 영상(세계가 바뀌는 콘셉트, `api/_lib/video-prompt.js` `conceptPrompt`) + 브라우저 후편집(`src/videoCaptioner.ts`, 고급형 스타일). 포스터·홍보 글은 그대로.
- **왜 결과 화면인가:** 입력 화면의 "고급" 분위기 버튼과 겹치지 않고, 기본 결과를 먼저 본 뒤 원할 때만 1~3분을 더 기다린다. 시연에서 "기본 → 특급" 차이를 눈앞에서 보여 줄 수 있다.
- **누가 보나:** 시연 코드 기기만. Vercel 환경 변수 `PREMIUM_ACCESS_CODE`, 시연 휴대폰에서 `https://주소/?demo=코드`로 한 번 열면 그 기기에 기억(`src/premiumAccess.ts` `hasPremiumCode`), 서버도 `x-premium-code`를 확인(`api/_lib/paid.js`). 이미 만들어져 있음.
- **어디:** `src/App.tsx` 영상 탭(지금 `startPremium`·`aiVideo.start`·`premiumSteps`가 있는 곳), `src/AiVideoPanel.tsx` 진행 단계. 기존 "고급형 특별 연출" 스위치(`SpecialFilmToggle`, `details.specialFilm`)와 사진 화면의 기본형/고급형 선택(`VideoModeToggle`)은 C안 구현 때 없애거나 숨긴다.
- **먼저 고칠 것:** 콘셉트 영상 실제 1번(2026-10-18)에서 ① 테이블에 가짜 글자 ② 밀가루가 케이크를 덮음 ③ 제품이 화면의 약 20%로 작음. → [특급-품질] 항목.
- **끝난 기준:** 시연 코드 기기에서만 버튼이 보이고, 누르면 진행 단계 → 완성 영상으로 바뀜. 코드 없는 기기에는 버튼이 없고 서버도 거절(`verify:guard`). 같은 사진으로 두 번 눌러도 결제 1번(결제 키). `verify:video`에 검사 추가.
- **비용:** 1번 약 300~450원(Kling 2.5 Turbo 5초). 시험 호출은 사용자 승인 횟수 안에서, 쓰기 전에 [디자인개선_루프.md](디자인개선_루프.md) "호출 사용량"에 먼저 기록.

## [특급-품질] 콘셉트(특급) 영상 프롬프트 다듬기

- **상태:** 보류([특급]과 함께).
- **무엇:** `conceptPrompt`의 세계 문장을 "제품 앞을 스쳐 지나가고 제품에는 닿지 않음"으로, 부정 프롬프트(`CONCEPT_NEGATIVE_PROMPT`)에 signage·engraved text·inscription 추가, 마지막 장면 제품 크기 "화면 높이의 절반" 명시. 입력 사진은 앱처럼 9:16으로.
- **끝난 기준:** 유료 1~2번으로 가짜 글자 없음, 제품이 가려지지 않음, 제품이 충분히 큼. 자막 아래 띠 흐림(이미 있음)으로 남는 글자도 가려짐.
- **비용:** 1번 약 300~450원.

## [회원가입] Supabase Auth + 내 홍보물 서버 저장

- **상태:** 보류 — "나중에"(사용자, 2026-10-19). 시연 2주차 앞에 할 계획.
- **무엇:** 로그인 화면(이미 카카오·네이버·Google·아이디 버튼 있음, 지금은 "준비 중")을 실제로 연결. Supabase Auth(카카오 기본 지원, 네이버는 별도 OIDC 필요할 수 있음). 내 홍보물(지금 기기 IndexedDB, `src/recordsStore.ts`)을 Supabase DB로.
- **결정이 필요한 것:** 로그인 방식(카카오만 / 카카오+Google / 아이디 포함), 비로그인 사용 허용 여부("바로 시작하기" 유지), 저장 기간·용량(사진은 줄여서 저장).
- **주의:** Vite + Vercel 함수 구조라 Next.js 전용 모듈(NextAuth 등)은 안 맞는다. GitHub에서 모듈을 가져오면 라이선스(MIT·Apache 가능, AGPL 피함)와 최근 6개월 관리 여부 확인. **개인정보 처리방침**(무엇을 왜 모으는지) 화면 필요. 키는 서버 환경 변수로만.
- **로드맵 연관:** 로그인이 실제로 생기면 "로그인"을 다시 주 버튼으로(`reference-ui.css` 끝의 로그인 규칙 두 줄 삭제) — [품질개선_로드맵.md](품질개선_로드맵.md) "코드 구조 정리".
- **끝난 기준:** 휴대폰에서 가입·로그인·로그아웃, 다른 기기에서 같은 계정으로 내 홍보물이 보임, 비로그인으로도 만들기 가능(정한 경우), 검증 스크립트 추가.

## [제품합성] 제품만 오려 내고 배경만 AI로 만들어 합치기

- **상태:** 조건부 — 배경 바꾸기 프롬프트 보강으로 제품 변형(마카롱 흰 꼬끄 → 베이지, 2개+꼬끄 → 3개)을 막지 못하면 한다.
- **무엇:** 원본에서 제품 영역을 오려 내고(배경 제거), Gemini에는 빈 배경만 그리게 한 뒤 브라우저에서 합성. 제품 픽셀이 절대 바뀌지 않는다.
- **주의:** `@imgly/background-removal`은 AGPL·모델 40~80MB라 피한다. 후보: Gemini 분할 마스크, 서버 쪽 가벼운 모델.
- **끝난 기준:** 마카롱·케이크·라테 사진에서 제품 픽셀이 원본과 같고 경계가 자연스러움.

## [사진먼저-잘림] "사진 먼저" 포스터에서 세로 AI 장면의 위쪽이 잘림

- **상태:** 보류. 자르는 위치만 옮기는 방법은 2026-10-18에 시험했으나 효과가 없어 버림.
- **무엇:** AI 배경 사진에서도 제품 위치(상자)를 알아서 `focusBox`로 넘긴다(지금은 장면 사진이면 `focusBox: null`). 배경을 만들 때 원본의 상자를 장면 좌표로 옮기거나, 장면 사진을 한 번 더 분석.
- **끝난 기준:** 케이크 장면 "사진 먼저" 4:5에서 케이크 윗부분이 잘리지 않음, `eval:poster` 100 유지.
