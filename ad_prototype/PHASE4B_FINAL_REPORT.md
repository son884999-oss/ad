# 홍보잇다 Phase 4-B — 브랜드 에셋 확장·화면 정교화 결과

작성: 2026-10-10. 사용자 승인 C안 ‘오가는 흐름’을 유지하고 **로고 구성 8개와 신규 서비스 삽화 12종, 총 20개 창작 단위**를 완성했다. 주요 삽화 12종을 실제 React 화면에 모두 연결하고 최종 화면·기능 검증을 통과했다.

프로젝트의 지침 파일은 `HASE4B_MASTER.md`다. 최신 수정본 전체와 `AGENTS.md`, `DESIGN_MASTER.md`, Phase 4-A·승인 후 브랜드 작업을 읽고 완료 기준을 적용했다. 사용자 지침 파일의 이름이나 내용을 임의로 바꾸지 않았다.

사용자가 수정한 `HASE4B_MASTER.md`의 최우선 UX·시각 명료성·접근성 기준과 추가 요청을 반영했다. **주 타겟은 시니어**이며, 에셋 개수보다 읽는 글자와 다음 행동의 위계가 먼저다. 읽어주기를 설정 밖의 첫 줄에 스피커 모양 SVG와 함께 항상 노출하고, 시작 버튼 → 3단계 안내 → 결과 예시 순으로 재배치했다. ‘3초 이해’는 자체 검토를 위한 기준이며 실제 3초 인지 실험을 수행했다고 주장하지 않는다.

## 1. 최종 브랜드

공식 이름은 **홍보잇다**다. C안의 비대칭 무한 고리, 오른쪽으로 올라가는 끝, 주황·남색 교차를 유지했다. 가로 조합·한글·심볼은 순수 SVG path이며 별도 폰트 다운로드 없이 정확히 홍·보·잇·다를 표시한다. 기본 가로 로고는 2,918 bytes다.

기존 C안의 7개 목적별 구성을 유지하고, 로그인에 적합한 심볼 위·한글 아래의 세로 기본 조합을 추가했다. 헤더·메뉴에는 가로 로고, 로그인에는 세로 조합, 푸터에는 한글 워드마크, favicon·홈 화면 저장에는 정사각 아이콘을 연결했다. 반전·단색 배포본은 브랜드 라이브러리에서 제공하며 모든 제품 화면에 중복 노출하지 않는다.

주황 `#E88942`는 심볼·이미지에, 진한 주황 `#AD4A19`는 주요 행동에, 남색 `#26364A`는 읽는 글자에 사용한다. 아이보리 `#FFF8EF`와 피치가 중심 배경이다. 보조 글자 `#625E59`는 피치 카드에서도 읽을 수 있도록 대비를 확보한 값이다. 기존 민트·하늘색은 보조색으로 사용한다.

브랜드 사용 기준: [BRAND_GUIDE.md](public/assets/branding/selected/BRAND_GUIDE.md). 글꼴의 저작권·SIL OFL은 같은 폴더 `FONT-LICENSE.txt`에 보관한다.

## 3. 실제 생성과 원본 보관

공식 `imagegen` 스킬의 내장 `image_gen` 경로로 삽화 12종을 제작했다. 히어로 최초 생성 1회, 같은 장면을 다듬는 편집 1회, 나머지 11종의 별도 생성으로 총 **13회** 사용했다. 다른 삽화에는 선택한 히어로를 스타일·팔레트 참조로 전달했다. CLI·별도 유료 API로 전환하지 않았다.

원본 PNG·실제 프롬프트는 `design-assets/illustrations/phase4b/`에 보관했다. 최초 히어로 `service-hero-v1.png`도 남겼다. 배포본은 WebP이며 생성 이미지가 편집 가능한 벡터 원본이라고 주장하지 않는다. 로고와 기능 아이콘은 별도의 코드 기반 SVG다.

최적화는 기존 Playwright 브라우저의 Canvas로 크기와 포맷만 변환했다. 작은 삽화 11종의 실제 alpha를 유지하고, 원본을 삭제하거나 투명 영역을 불투명 바탕으로 일괄 합성하지 않았다. 대표 장면은 아이보리 배경이다. `ServiceArt`는 치수, alt, lazy loading과 대표 이미지의 `srcSet`·high priority를 공통으로 관리한다.

## 4. 교체한 그래픽과 인물 비중

기존 홈의 큰 사장님 2명 중심 이미지를 큰 포스터·영상·글 결과 창, 매장, 입력 휴대전화 중심의 대표 장면으로 교체했다. 최초 새 이미지의 사진 같은 제품 질감과 큰 인물을 확인하고, 제품을 평면 도형으로 바꾸고 인물을 작은 전신 성인 1명으로 줄였다. 새 대표 장면의 인물은 약 30–40세의 어두운 머리 성인으로, 결과 화면을 가리지 않는 보조 역할이다. 다른 11종에는 인물을 넣지 않았다.

홈 3단계의 기존 인물 삽화는 사진 선택·설명 입력·결과 카드라는 작업 장면으로 교체했다. 빈 상태에 재사용하던 사진 선택 그림도 실제 빈 보관함 장면으로 바꿨다. 홈의 기능 소개에는 단순 아이콘만 있던 자리에 포스터·영상·글을 보여주는 설명 이미지를 넣었다. 사진 업로드·저장 후 안내·글 복사에도 해당 동작을 설명하는 장면을 연결했다.

이번 작업 시작 시 source에 중요한 장식 이모지는 남아 있지 않았다. 최종 source 검사에서도 장식 이모지가 없음을 확인했다. 존재하지 않던 이모지를 대량 교체했다고 보고하지 않는다. 체크·화살표·사진·영상·설정·내비게이션 등의 명확한 기능 SVG는 보존했다.

사용자가 넣은 사진과 실제 포스터·영상 미리보기는 설명용 삽화로 대체하지 않았다. 기능 회귀 검사에서는 기존 fixture도 사용했고, 최종 전용 캡처에는 신규 포스터 PNG를 입력해 서비스 중심 결과 화면을 확인했다.

## 5. 메인 화면과 시니어 사용성

첫 줄에서 스피커 모양과 큰 **화면 읽어주기** 버튼을 바로 찾을 수 있다. 읽기 준비 중에는 취소, 읽는 중에는 멈추기로 바뀌며 기존 음성 준비·복구 동작을 유지한다. 간편모드의 켜짐 여부나 설정을 펼치는 동작과 관계없이 버튼이 보인다. 설정에는 글씨·알림만 남겼다. 자동으로 읽기 시작하지는 않는다.

홈은 읽기 도움 → 서비스 소개 → **홍보물 만들기** → **이렇게 세 단계면 돼요** → 예시 이미지 → 개별 기능 순이다. PC에서도 결과 예시보다 단계 안내가 먼저다. 작은 화면의 단계 설명은 큰 글자와 짧은 문장으로 정리했다. 실제 `StepProgress`를 다시 만들지 않았다.

PC의 짧은 소개와 시작 버튼은 가운데에 모아 넓은 화면에서도 행동을 쉽게 찾도록 했다. 모바일 문장과 입력란은 읽기 쉬운 왼쪽 정렬을 유지한다.

작은 삽화는 설명 옆의 보조 요소로 사용한다. 읽어야 할 글자는 이미지에 넣지 않고 실제 한국어로 제공한다. 대표 장면에는 의미 있는 alt, 주변 설명을 반복하는 작은 장면에는 빈 alt를 사용했다.

좁은 화면에서 사진 선택 삽화가 문구를 아래로 밀어 하단 메뉴에 가리는 문제를 실제 검사로 발견했다. 문구를 이미지보다 먼저 배치하고 모바일 이미지 크기를 88px로 줄였다. 기존 검사 조건을 완화하지 않고 수정 후 통과했다.

사진 선택 문구를 주황 버튼처럼 구별해 누를 곳이 분명하도록 했다. 설명 화면에서는 반복 안내 이미지를 제거하고, 제목·예시를 짧게 정리했다. 선택 사진·홍보물 확인은 입력란 뒤의 펼침 영역에 보존했다. 작은 화면의 첫 입력란은 화면 위쪽에서 **약 634.5px**, 모든 검사 너비에서 700px 이전에 표시된다. 복잡한 선택 정보가 필수 입력보다 앞서지 않는다.

## 6. 세 관점과 반복 개선

| 관점 | 문제 | 실제 개선 |
|---|---|---|
| 시니어 UX | 인물 위주의 그림, 업로드 첫 행동의 가림, 저장 후 해야 할 일의 추상적 안내 | 서비스 결과 중심 장면, 사진 선택 문구 우선, 저장·복사·수동 게시 장면 |
| 프론트엔드 | 화면별 이미지 속성 분산, 새 이미지로 기존 범용 테스트 선택자 충돌 | `ServiceArt` 공통 속성, 원본·manifest·최적화 스크립트, 오류 복구 검사의 대상을 실제 `.selected-photo`로 지정 |
| 디자인 | 기존 세이지·인물 이미지와 새 주황 브랜드의 불일치 | 아이보리·주황·남색 팔레트, 인물이 작은 히어로, 12종의 동일 제품·선·색상 계열 |

이 검토는 세 전문 관점의 자체 검토이며 별도의 전문가 인터뷰·독립 에이전트·시니어 사용자 실험 결과가 아니다.

**4회 주요 개선 주기**를 수행했다.

1. 현재 구현·에셋·기능 확인, 복원 지점, 20개 목적별 계획, 대표 장면 생성·정교화.
2. 나머지 11종 생성·실제 검토·최적화, 로고 세로 조합, 모든 React 적용 위치 연결.
3. 실제 모바일·PC 캡처, 42개 화면 검사, 사진 선택 가림 수정, 안정된 전환 후 재캡처, 전체 회귀·빌드 검증.
4. 수정된 최우선 지침과 시니어 타겟 요청을 반영해 읽어주기 첫 줄 노출, 시작 버튼 아래 3단계, 그 뒤 예시 이미지로 위계 수정. 실제 입력란의 초기 위치를 확인하고 중복 설명·선택 정보의 우선순위를 낮춘 뒤 재검증.

수정 지침의 여섯 질문도 실제 화면에 대조했다. 첫 행동은 홈의 시작 버튼·사진 선택·제품 설명 입력란으로 명시하고, 핵심 CTA의 진한 주황과 읽기 도움의 옅은 주황을 구별했다. 모바일 한글은 18–22px 중심으로 유지한다. 삽화는 안내·예시·선택 사항·결과 상태에 분산되어 있으며 설명 입력란 앞의 중복 삽화는 제거했다. 사진·설명·결과·저장은 기존 단계와 결과 이동 링크로 찾을 수 있다. 이는 자체 화면 검토이며 시니어 인지 실험 결과가 아니다.

이미지 생성에 맞춰 완료 기준을 축소하거나 파일만 만든 상태에서 종료하지 않았다.

## 7. 반응형·실제 구현 증거

`verify-phase4b.mjs`는 320/375/390/430/768/1024/1440px에서 홈·사진·채널·설명·결과·빈 기록의 **42개 화면 상태**를 확인했다. 이미지 누락과 가로 넘침이 없고, 실제 표시된 본문 버튼이 44px 이상이며 첫 주 행동이 화면 상단 700px 안에 있다. 삽화 12개를 실제 렌더링한 URL로 모두 확인했다. 파일 존재·manifest만으로 통합을 판단하지 않았다.

긴 페이지 캡처에 고정 하단 메뉴가 중간에 찍히는 것은 최초 viewport의 고정 위치가 포함되는 캡처 특성이다. 첫 사진 선택의 실제 가림은 별도로 `elementFromPoint`로 검사했다. 처음의 화면 전환 도중 찍힌 흐린 캡처는 안정된 전환 뒤 다시 캡처했다.

## 9. 수정 파일과 복원

수정: `src/App.tsx`, `BrandLogo.tsx`, `ChannelPicker.tsx`, `PhotoStep.tsx`, `PublishingGuide.tsx`, `StudioScreens.tsx`, `experience.css`, `index.css`; `scripts/build-selected-brand.mjs`, `verify-selected-brand.mjs`, `verify-recovery.mjs`, `verify-phase3.mjs`; 브랜드 사용 기준. 앱 로직의 재구성이나 진행 컴포넌트의 교체는 하지 않았다. Phase 3 검사의 예시 이미지가 첫 화면에 있어야 한다는 조건은 사용자 요청에 맞춰 ‘시작 행동 다음 단계 안내, 그 뒤 예시’라는 실제 순서 검사로 변경했다.

추가: `src/ServiceArt.tsx`, `src/brand-assets.css`, `src/senior-hierarchy.css`; `checkpoint-phase4b.mjs`, `optimize-phase4b-assets.mjs`, `build-phase4b-library.mjs`, `review-phase4b.mjs`, `verify-phase4b.mjs`, `audit-phase4b-completion.mjs`; `primary-stacked.svg`; 신규 PNG·프롬프트·WebP·manifest; `public/brand-library/`; 계획·목록·이 보고서.

복원 파일은 `../.phase4b-checkpoint-20261009/files/`, SHA-256 기준은 같은 폴더의 `baseline.json`이다. **83개 사본을 실제 해시로 검증**했다. 초기 ZIP 생성은 파일 잠금 때문에 실패해 검증된 파일별 사본으로 대체했다. 실패한 ZIP을 복원 지점이라고 안내하지 않는다. 기존 사용자 미커밋 변경을 포함한 사본이며 강제 reset·checkout을 사용하지 않았다.

최종 검증 상태도 `../.phase4b-verified-20261010-final/files/`와 `baseline.json`에 별도로 보관한다. 제작 스크립트는 이미 만들어진 복원 지점을 덮어쓰지 않도록 보호하며, 사본과 원본의 해시가 일치하는지 확인한다.

`StepProgress`, 알림 Provider·설정, 채널 계약, Canvas 줄바꿈, package·Vite·AGENTS는 시작 기준과 일치한다. 이전 삽화와 5개 로고 탐색안도 보존했다. 사용자 수정 `HASE4B_MASTER.md`는 다시 전체를 읽고 반영했다. `DESIGN_MASTER.md`의 ‘system’이 ‘sys tem’으로 바뀐 공백 차이도 되돌리지 않았다. 지침 변경을 우리 코드 변경 목록으로 합산하지 않았다. [완료 근거 검사](ui-review/phase4b-final/completion-audit.json)에 실제 변경 목록을 기록했다.
