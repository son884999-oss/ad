# 홍보잇다 결과물 품질 기준

홍보잇다는 사장님이 사진 한 장과 몇 줄을 넣으면 **가게에 바로 올릴 수 있는** 포스터·영상·홍보 글을 만들어 주는 모바일 웹앱이다. 사용자는 고령 소상공인이 많다. 그래서 기준은 하나로 모인다: **처음 본 손님이 1초 안에 무엇을, 얼마에, 어디서 파는지 알 수 있는가.** 아래 규칙은 모두 이 질문에서 나왔고, 대부분 실제 결과물에서 문제를 겪은 뒤 정한 것이다(이유를 같이 적었다).

작업 위치: `ad_prototype/` (팀 폴더 `A_*`~`F_*`는 읽기만). 진행 규칙은 `ad_prototype/docs/자동작업_프롬프트.md`, 바퀴별 기록은 `ad_prototype/docs/디자인개선_루프.md`.

## 1. 포스터 (`src/poster/posterRenderer.ts`)

기준 그림은 사용자가 "이것보다 못하면 안 된다"고 정한 하한선이다.

| 화면 이름 | 코드 (`compositionKey`) | 렌더 함수 | 기준 그림 |
|---|---|---|---|
| 사진 크게 (기본) | `vertical` | `renderFullBleedPoster` | `public/assets/reference-fresh/poster-coffee.webp` |
| 사진 먼저 | `editorial` | `renderPanelPoster` | **`ad_prototype/docs/기준그림/사진먼저_라테_4x5.webp`** (2026-10-18 사용자가 "가장 예쁘다"고 고정. 골목커피 하트 카페라테, 시연 결과 JSON 문구) · 예전 기준 `public/assets/reference-fresh/poster-example.webp` |
| 나란히 | `split` | D_고혜숙 원본 | — |

- **사진이 주인공.** "사진 크게"는 사진이 화면을 꽉 채우고 아래 어두운 그라데이션 위에 흰 큰 제목·설명·큰 가격을 얹는다. "사진 먼저"는 위 사진이 크림색 판으로 이어지고 가운데 정렬. 사진이 작게 들어간 카드형은 "초라하다"는 평을 받아 버렸다.
- **글 양에 따라 판 크기를 맞춘다.** 글이 적은데 판이 반이 비면 미완성처럼 보인다. 먼저 글을 재고 남는 자리를 사진에 준다.
- **가격은 가장 크게, 따로.** 숫자+원이 든 항목은 큰 가격 줄로, 나머지 특징은 배지 한 줄로 합친다(두 번째 가격이나 "당일 예약"이 사라지면 안 됨).
- **글자 대비 4.5:1 이상**(큰 제목 3:1). 밝은 사진 위 가게 이름은 반투명 어두운 알약 위에 둔다.
- **9:16 스토리 안전 영역**: 위 250px·아래 340px에는 글자를 두지 않는다(인스타·릴스 버튼이 덮는다).
- **제목 최대 2줄**, 넘치면 "…". 제품명 26자가 넘으면 입력란에 "포스터에는 앞부분만 들어가요" 안내.
- **AI 문구를 썼으면 "AI 활용" 표시**(인공지능기본법 제31조). 사진만 쓴 기본 결과에는 넣지 않는다.

## 2. 영상

세로 9:16(1080×1920)이 기본이다. 정사각 영상은 릴스·쇼츠에서 위아래가 검게 나와 실패로 본다.

### 기본형 (무료, 브라우저에서 그림: `src/motionVideo.ts`)
- 6초 3장면: 확대(가게 이름·제목) → 제품 가까이 + 빛 스침 + 특징 태그 → 끝 카드(제품명·가격·행동 유도).
- 업종별 움직임 1개만(E_이채원 분류): 음식 김, 화장품 반짝임, 꽃 꽃잎, 생활용품 빛. 과하면 싸 보인다.
- 사진은 AI 영상과 같은 9:16 구도(`drawStoryFrame`)로, 제품 옆이 잘리면 안 된다.
- 자막은 포스터 스타일(`drawVideoCaption`): 아래 어두운 페이드, 큰 흰 제목, 흰 알약 행동 유도.

### 고급형 (유료: `api/_lib/scene.js`, `video-prompt.js`)
- **배경 바꾸기 먼저**: 제품은 그대로 두고 주변만 업종별 광고 세트로 바꾼 장면 1장 → 그 장면으로 포스터와 AI 영상을 같이 만든다.
- **AI에게 글자를 절대 시키지 않는다.** "라벨이 읽히게"라는 지시 하나로 컵에 가짜 상표 "Ploystalis"가 생겼다. 사진에 있는 글자만 유지, 새 글자 금지를 프롬프트와 negative 둘 다에 넣는다. 글자는 후편집(`videoCaptioner.ts`)으로만.
- 고급형 자막은 참고 광고(쵸이셀 리디자인) 스타일: 왼쪽 아래 작고 조용하게 — 자간 넓은 라벨, 가는 감성 문구, 제품명, "…에서 만나보세요 →" (`drawElegantCaption`).
- **비용 안전**: `VIDEO_ENABLED=1` 없으면 서버가 503. 같은 사진+내용은 같은 결제 키(재시도·실패 후 다시 만들기 포함). 서버는 절대 자동 재시도하지 않는다. 시험 호출은 사용자 승인 범위 안에서만, 쓰기 전에 루프 문서의 사용량을 먼저 올려 커밋한다.

## 3. 홍보 글 (`api/_lib/promo.js`, `promo-prompt.js`, `src/localCopy.ts`)

- **상투어 금지**(정성·최고·프리미엄·특별한…): 사장님이 직접 쓴 말이면 허용. 다시 써도 남은 꾸밈말(정성껏·최고급·엄선된…)은 코드로 지운다.
- **효능·확인 안 된 주장 금지**(치료·다이어트·무첨가·1위·유일…): 식약처 광고 기준.
- **AI 말투**("~를 통해", "다양한", "선사합니다", "당신") 2개 이상이면 다시 쓰게.
- **행동 유도 한 줄**(들러 보세요·예약·문의), 첫 줄 40자 이내, 해시태그 3~5개.
- **AI가 안 될 때의 기본 문구도 같은 기준**: 무료 키는 하루 20번뿐이라 많은 사용자가 기본 문구를 본다. 양식 나열(✔ 체크, 이름만 줄줄이)이 아니라 제목 줄 → 문장 → "특징·위치·가격·문의 ·" 이름표 줄 → 추천 → 곳별 마지막 한 줄.

## 4. 화면(UI) — 고령 사용자 기준

- 한 화면에 주황 주 버튼은 하나. 선택된 항목은 "테두리 + 옅은 바탕"으로 통일(꽉 찬 주황은 주 버튼 전용).
- 글자 14px 이상(쉬운 화면 더 크게), 누르는 곳 44px(쉬운 화면 52px) 이상, 대비 4.5:1.
- 짧은 안내는 `text-wrap:balance; word-break:keep-all` — "주세요."만 홀로 다음 줄로 가지 않게.
- 휴대폰 뒤로가기는 앱 안에서 한 단계 뒤로. 200% 확대(폭 195px)에서도 버튼이 밖으로 밀리면 안 된다.
- 아직 안 되는 기능(로그인)이 주 버튼이면 안 된다.

## 5. 점검 명령 (ad_prototype 폴더에서)

브라우저 테스트는 개발 서버(5173, 실제 키가 있음)를 쓰므로 **`/api/**`를 항상 가짜 응답으로 막고** 돌린다. 직접 눈으로 볼 때는 `pnpm dev:mock`(5174, 키를 읽지 않음).

| 무엇 | 명령 | 통과 기준 |
|---|---|---|
| 타입·빌드 | `npx tsc --noEmit -p .` · `npm run -s build` | 오류 0 |
| 기능 검증 | `npm run -s verify:easy` · `verify:photo` · `verify:records` · `verify:video` · `verify:ai` · `verify:promo` · `verify:scene` · `verify:guard` | 모두 PASS |
| 화면 회귀 | `REFERENCE_REBUILD_OUTPUT=<dir> node scripts/verify-reference-rebuild.mjs` | PASS |
| 화면 측정 | `npm run audit:screens -- --shots <dir>` (360·390·430·PC틀 × 기본·쉬운) | 문제 0개 |
| 포스터 | `npm run eval:poster -- http://127.0.0.1:5174/ --layout vertical --out <dir>`, 같은 명령을 `--layout editorial`로 한 번 더 (한 번에 사진 3 × 비율 3 = 9장) | 두 번 다 9장 모두 100 + 눈으로 확인 |
| 영상 | `npm run eval:video -- http://127.0.0.1:5174/ --out <dir> [--times 0.8,2.2,3.6,5.6]` (실제 클립은 `--file clip.mp4`) | 자막 대비 기준 통과 + 프레임 눈으로 확인 |
| 홍보 글 | `npm run eval:promo` (오프라인) · `-- --local` (기본 문구) · `-- --live --names …` (Gemini, 하루 20번 한도 주의) | 90점 이상 |

`eval:poster`·`eval:video`·`audit:screens`는 스스로 `/api/**`를 막으므로 5173·5174 어느 쪽이든 안전하다. 주소를 첫 인자로 넘긴다.

**측정이 재는 것과 재지 않는 것.** `eval:poster`는 대비·안전 영역·사진 면적·제목 줄 수만 잰다. 가격 크기·분리, 정보 잘림("…"), 빈 판, AI 표시 여부는 재지 않으므로 반드시 눈으로 본다. 기본 사례에 없는 경우(가격 2개+예약 같은 긴 특징, 이름만 있는 짧은 글, 긴 제품명)는 브라우저에서 `/src/poster/posterRenderer.ts`의 `renderPosterToCanvas`를 직접 불러 그려 본다(`scripts/eval-poster.mjs`의 `page.evaluate` 부분을 본뜨면 된다).

측정이 통과해도 **캡처를 직접 본다.** 측정 스크립트가 틀린 적이 여러 번 있었다(그라데이션 대비, 닫힌 펼침 속 버튼, 키보드 검사 뒤 캡처). 점수가 이상하면 먼저 측정을 의심하고, 측정을 고쳤으면 커밋 본문에 이유를 적는다.

## 6. 채점

영역마다 100점에서 시작해 이 문서의 규칙을 어길 때마다 깎는다(같은 규칙은 한 번만).
- 측정으로 잡힌 위반(대비·안전 영역·겹침·가로 스크롤 등): −10
- 눈으로 본 위반(가격이 작거나 섞임, 정보 잘림, 빈 판, 어색한 여백, 주 버튼 2개 등): −5
- 홍보 글은 `eval:promo` 점수를 그대로 쓴다.

근거(파일·캡처 경로·수치)를 함께 적는다. 목표 90점.

## 7. 작업 방식

**점검만 요청받았을 때**("고치지 마"): 해당 영역의 측정 명령과 눈으로 확인만 하고, 6절대로 채점해 근거와 고칠 점을 우선순위로 보고한다. 파일은 임시 폴더에만 쓰고 커밋하지 않는다.

**고칠 때:**

1. 바꾸기 전 지금 결과를 위 기준으로 채점하고 근거를 적는다.
2. 점수를 가장 많이 올릴 문제 하나만 고친다.
3. 5절 점검을 모두 통과 → 같은 기준으로 다시 채점 → 오르지 않았으면 버린다.
4. 커밋(영어 요약 + 본문, 끝에 Co-Authored-By) → `feature/UI-Screen`에 푸시 → `docs/디자인개선_루프.md` 기록 표에 한 줄.
5. 비용이 들거나 흐름을 바꾸는 큰 일은 하지 말고 `docs/품질개선_로드맵.md`에 적는다.
