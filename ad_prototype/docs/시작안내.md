# 시작 안내 — 다른 컴퓨터에서 이어서 작업하기

클로드 코드가 새 컴퓨터에서 이 프로젝트를 열면 **이 문서 하나와 저장소 맨 위 `CLAUDE.md`만 읽고** 바로 이어 갈 수 있게 정리했다.
마지막 갱신: 2026-10-19 · 브랜치 `feature/UI-Screen`

## 1. 받기와 설치 (처음 한 번)

```powershell
git clone <저장소 주소> ad
cd ad
git checkout feature/UI-Screen
cd ad_prototype
npx -y pnpm@9.15.9 install      # pnpm 버전을 맞춰야 함(다르면 패키지 저장소가 어긋남)
```

- Node: 24.x로 작업함(22 이상이면 됨).
- 자동 점검은 Playwright가 **Microsoft Edge**(`channel: "msedge"`)를 쓴다. Windows에는 기본으로 있으므로 따로 받을 브라우저는 없다.
- ffmpeg는 앱 실행에 필요 없다(음원 편집·비교 그림용, 있으면 편함).

## 2. `.env.local` 다시 만들기 (git에 없음, 직접)

`ad_prototype/.env.example`을 복사해 `ad_prototype/.env.local`로 만들고 값을 넣는다. **값은 채팅·문서·커밋에 붙이지 않는다.** 클로드는 이 파일을 읽거나 출력하지 않는다.

| 이름 | 무엇 | 없으면 |
|---|---|---|
| `COPA_API_KEY` | 기관 Claude (글 AI 1순위) | Gemini로 대체 |
| `GEMINI_API_KEY`, `GEMINI_MODEL` | Gemini 무료 키 (글) | 앱 기본 문구 |
| `GEMINI_API_KEY_2`, `GEMINI_MODEL_2` | Gemini 유료 키 (글 대체 + **배경 바꾸기**) | 배경 바꾸기 꺼짐 |
| `GEMINI_IMAGE_MODEL` | (선택) 배경 모델. 비우면 `gemini-3.1-flash-lite-image` | 기본값 사용 |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | 회원가입·로그인·서버 저장 | 로그인 "준비 중" |
| `HF_CREDENTIALS`, `VIDEO_ENABLED`, `PREMIUM_ACCESS_CODE` | 특급 영상(보류 중) | 비워 둠 |

키를 넣은 뒤 `npm run dev` → http://localhost:5173 . Supabase 값이 맞는지는 메뉴 → 로그인 · 회원가입으로 확인.

## 3. 새 컴퓨터로 넘어가지 않는 것

| 무엇 | 왜 | 어떻게 |
|---|---|---|
| `.env.local` | 키(비밀) | 2절대로 다시 만듦 |
| `ad_prototype/outputs/` 전체 | git 제외(결과물·로컬 문서) | 필요하면 USB 등으로 직접 복사 |
| ↳ `outputs/내부문서_로컬/` | 사용자가 공유하지 않기로 한 문서(기술 상세본, 자체 개발 설명, 추후 검토 과제 장) | 직접 복사 |
| ↳ `outputs/.gemini-key2-usage.json` | 유료 키 하루 사용 장부(이 컴퓨터 기준) | 새 컴퓨터는 0원부터 셈 — 같은 날 두 컴퓨터를 쓰면 실제 사용은 합쳐서 생각 |
| 클로드의 사용자 메모리 | 이 PC의 `~/.claude`에만 있음 | 중요한 규칙은 `CLAUDE.md`에 이미 있음 |

내부 테스트용 홍보 문구는 `docs/기준문구/홍보글_채널별_{케이크,라테}.json`(저장소에 있음)을 쓴다. AI를 다시 부르지 않는다.

## 6. 점검 명령 (바꾼 뒤에는 꼭)

개발 서버(`npm run dev`, 5173)를 켜 둔 상태에서:

```powershell
npx tsc --noEmit -p .
npm run build
npm run verify:ai; npm run verify:video; npm run verify:easy; npm run verify:records; npm run verify:photo
npm run verify:promo; npm run verify:guard; npm run verify:scene; npm run verify:background; npm run verify:auth
$env:REFERENCE_REBUILD_OUTPUT="$env:TEMP\rebuild"; node scripts/verify-reference-rebuild.mjs
npm run audit:screens -- --shots "$env:TEMP\audit"
npm run eval:poster -- http://127.0.0.1:5173/ --layout vertical --out "$env:TEMP\poster-v"
npm run eval:poster -- http://127.0.0.1:5173/ --layout editorial --out "$env:TEMP\poster-e"
npm run eval:video -- http://127.0.0.1:5173/ --out "$env:TEMP\video"
npm run eval:promo; npm run eval:promo -- --local
```

유료 AI는 점검에서 부르지 않는다(가짜 응답). 기준과 눈으로 볼 것: `.claude/skills/hongboitda-quality/SKILL.md`.

**마지막 전체 점검 (2026-10-19 저녁): 모두 통과.** tsc · build · verify 10종(ai 17, video 26, easy 7, records 5, photo 14, promo 34, guard 8, scene 6, background 11, auth 4) · 화면 35개 재현 · audit:screens 문제 0 · eval:poster vertical·editorial 각 100점 · eval:video 자막 대비 통과 · eval:promo 오프라인·기본 문구 100점. 참고: 전부 연달아 돌리면 verify:video가 영상 탭 대기에서 한 번 시간 초과될 수 있음 — 단독으로 다시 돌리면 통과(컴퓨터 부하). 그 뒤 소리 조정(videoSound.ts) 후 verify:video·build 다시 통과.
